# ПОРТ HP2100 → СМ-2/СМ-2М

Статус: этапы 0–4 выполнены (18.11.2026).

## Этап 0. Подготовка

- Собран `BIN/hp2100` из ветки `sm2-port` (`make hp2100 ANSWER=N`).
- Барьер: `RegisterSanityCheck` — `*** Good Registers in HP 2100 simulator.`
- Версия: HP 2100 simulator V4.0-0 Release 29, git `c5f2dfc3`.
- Создан параметный блок `HP2100/sm2_params.h` — все корректируемые
  константы СМ-2 собраны в одном месте (память, векторы, коды выборки 2К,
  сигналы интерфейса, тайминги).

## Этап 1. Модель SM2/SM2M

Изменено:

| Файл | Что |
|---|---|
| `hp2100_defs.h` | `Option_SM2`, `Option_SM2M` добавлены сразу после `Option_1000_F`; маски `CPU_SM2`, `CPU_SM2M`, `CPU_SM2_SERIES` включены в `CPU_ALL` |
| `hp2100_cpu.c` | модельное поле расширено 017 → 037 (4 бита), сдвиг опций +4 → +5, маска опций 0003777 → 0001777; `UNIT_SM2/UNIT_SM2M`; строки в `cpu_features[]` (128К слов) и `cpu_mod[]` (`SET CPU SM2/SM2M`); `#include "sm2_params.h"` |

Проверка:

```
SET CPU SM2   → 32KW, SM2, loader disabled, no EAU
SET CPU SM2M  → 32KW, SM2M, loader disabled, no EAU
SET CPU 2116  → 32KW, 2116, loader disabled, no EAU   (без регрессии)
SET CPU 1000-E→ 32KW, 1000-E, EAU, FP, DMS            (без регрессии)
```

## Замеченная ловушка сборки

Изменение `hp2100_defs.h` **не вызывает** пересборку `.o` — make линкует
старые объекты и `SET CPU SM2` даёт сегментацию (`cpu_features[]` индексируется
старым OPTION_ID). Перед проверкой изменений в defs.h нужно:

```
touch HP2100/hp2100_cpu.c HP2100/hp2100_sys.c
rm -f BIN/hp2100
make hp2100 ANSWER=N
```

## Этап 2. Семантика СМ-2

- `is_sm2`, регистр `РАВ` (`sm2_rav`), флаг `ISSM2`.
- Пропуск увеличивает РНК на **2** (`SM2_SKIP_STEP` в `sm2_params.h`)
  в ISZ, CPA, CPB, ASG и SRG — только для моделей SM2/SM2M.
- `JSB` дополнительно сохраняет адрес возврата в РАВ.
- Дифференциальный тест: `ISZ 0200` → P=00103 в SM2, P=00102 в 2116.

## Этап 3. 17-разрядная адресация

- `sm2_mrg_address()`: 15-битный относительный адрес + РБ1 (сдвиг 9)
  или РБ2 (сдвиг 15), маска `SM2_LA_MASK` = 0x1FFFF;
  индексная/автоиндексная адресация через РИ1/РИ2 (биты 5,6 команды,
  бит 0 регистра = автоиндекс, знаковое смещение из битов 7–15).
- Регистры `RB1/RB2/RNG/RVG/RI1/RI2/SM2PRIV` доступны через SCP.
- Переходы и пропуски маскируются `SM2_ADDR_MASK` (17 бит для SM2,
  15 бит для HP — без регрессии).
- Проверка: `LDA 0100` с РБ1=1 читает ячейку 01100; с РБ2=1 вычисляется
  адрес 0100100 (см. `SAVEDMR`).
- GAP: физический доступ выше 32К слов требует модуля расширения памяти
  (12731A MEM); в текущей конфигурации адрес вычисляется, но память
  выше 32К недоступна. Будет закрыто в этапе 6.

## Этап 4. Двухсловные и дополнительные команды

- Новый модуль `hp2100_cpu8.c` с `sm2_ext_instruction()`, вызываемой из
  `machine_instruction()` для моделей SM2/SM2M (точка расширения `cpu_user`
  не использована — нужен полный перехват декодера).
- Реализованы: DLD, DST, MPY, DIV, LDX, LDY, STX, STY, LBN, LBP, FIX, FLT,
  FAD, FSB, FMP, FDV, TAS, двойные сдвиги ASR/ASL/LSR/LSL/RRR/RRL.
- Float: преобразование формата СМ-2М (знак в бите 0, мантисса 1–23,
  порядок 24–30 в дополнительном коде) через `double`.
- Проверка: `MPY` 3×5 → 017; `LDX` → РИ1=0122 (бит 0 сброшен);
  `DLD` → RA=011111, RB=022222; регрессия этапов 2–3 без изменений.

**GAP (важно):** в статье Савватеева приведены номера кодов операций,
но **не полные битовые раскладки**. Рабочая кодировка объявлена в
`sm2_params.h` (`SM2_OP_*`) и является нашей декларацией. Эмуляция
воспроизводит семантику команд, но **бинарная совместимость с подлинными
программами СМ-2 не гарантирована** — нужна точная таблица кодов.
