# TEAM_AGENTS.md — Координация агентов для проекта БЭСМ-6/Диспак

## Роли агентов

| Агент | Проект | Ответственность | Экономия токенов |
|-------|--------|-----------------|------------------|
| `lead` | все | Координация, планирование, финальные решения | — |
| `builder` | simh/BESM6 | Сборка, тестирование, мониторинг логов | ~40% на таймаутах |
| `coder` | simh/BESM6 | Точечное редактирование кода | ~25% на повторных чтениях |
| `emulator` | simh/BESM6 | Сложные задачи: ДКС, прерывания, команды | ~15% на анализе |
| `os-analyst` | re_dispak/re-dispak | Анализ модулей ОС, трассы, СВЯЗЬ7 | ~20% на поиске |

## Типичные задачи

### builder
- Сборка проекта: `make > /tmp/build.log 2>&1 &`
- Поиск ошибок: `grep -i error /tmp/build.log`
- Запуск эмулятора: `./BIN/besm6 dispak.ini &`
- Мониторинг ДКС: `tail -f debug.txt | grep -iE "(DKS|PRP)"`

### coder
- Точечные правки по спецификации
- Использование sed для простых замен
- Инкрементальное чтение (только нужные строки)

### emulator
- Реализация команд 032/132 (КАДОПАМ)
- Генерация прерываний ПРП5-8,12
- Регистрация DKS-терминалов
- Отладка kadopam_svc()

### os-analyst
- Проверка загрузки СВЯЗЬ7 (зона 0677)
- Анализ реакций на ПРП (процедуры H-терминала)
- Трассировка обмена через ДКС
- Комментарии к модулям ОС

## Координация

### Проблема: ОС не реагирует на прерывания ДКС
1. `builder`: собрать проект, проверить ошибки
2. `emulator`: проверить маски MGRP/MPRP, генерацию ПРП
3. `os-analyst`: проверить загруженность СВЯЗЬ7, вектора прерываний

### Проблема: Терминал не получает эхо
1. `emulator`: проверить dks_poll(), запись в kadopam_mem
2. `os-analyst`: проанализировать трассу МОТТ, буферы H-машины
3. `coder`: исправить код по результатам анализа

### Проблема: Ошибка компиляции
1. `builder`: найти строки с ошибками
2. `coder`: исправить только проблемные участки
3. `builder`: пересобрать и проверить

## Автоматический роутинг (Вариант 1)

### Правило: Lead автоматически делегирует задачи

При получении задачи от пользователя, lead анализирует ключевые слова и автоматически вызывает нужного агента через `team_run_task`.

### Таблица роутинга

| Ключевые слова | Агент | Пример задачи |
|---------------|-------|---------------|
| `собери`, `make`, `скомпилируй`, `ошибки компиляции`, `build`, `gcc` | `builder` | «собери проект» |
| `исправь`, `добавь функцию`, `измени строку`, `закомментируй`, `удали`, `edit`, `fix` | `coder` | «исправь dks_poll» |
| `ДКС`, `ПРП`, `КАДОПАМ`, `прерывание`, `команда 032`, `команда 132`, `kadopam`, `GRP`, `MRGP` | `emulator` | «проверь ПРП12» |
| `СВЯЗЬ7`, `модуль ОС`, `трасса`, `зона`, `Диспак`, `УКАЧКА`, `МОТТ`, `МИТТ`, `trace` | `os-analyst` | «проверь СВЯЗЬ7» |

### Алгоритм работы

```
1. Получена задача от пользователя
2. Анализ ключевых слов
3. Если есть совпадение → team_run_task(agentId, task)
4. Агент выполняет задачу
5. Результат возвращается пользователю
```

### Примеры автоматического делегирования

**Пользователь:** «собери проект»
**Lead:** → `team_run_task(agentId: "builder", task: "Собери проект: make > /tmp/build.log 2>&1 &, sleep 3, tail -30 /tmp/build.log")`
**Builder:** выполняет и возвращает результат

**Пользователь:** «исправь функцию dks_register в besm6_tty.c»
**Lead:** → `team_run_task(agentId: "coder", task: "Исправь функцию dks_register в besm6_tty.c")`
**Coder:** выполняет и возвращает результат

**Пользователь:** «проверь генерацию прерывания ПРП12»
**Lead:** → `team_run_task(agentId: "emulator", task: "Проверь генерацию прерывания ПРП12")`
**Emulator:** выполняет анализ и возвращает результат

### Составные задачи

Если задача содержит ключевые слова для нескольких агентов, lead разбивает её на подзадачи:

**Пользователь:** «найди ошибку компиляции в besm6_tty.c и исправь»
**Lead:**
1. → `builder`: «найди ошибки компиляции»
2. → `coder`: «исправь найденные ошибки»
3. → `builder`: «пересобери и проверь»

### Режим синхронизации

Все вызовы агентов — синхронные (`runMode: "sync"`), lead ждёт результата перед продолжением.
