### ❌ Нерешённая проблема: MPRP=0 (chicken-and-egg)
ОС не вызывает УСТРП → MPRP=0 → ДКС-прерывания не доставляются → СВЯЗЬ7 не загружается.

### Стратегии решения
- **А (оставлена):** Push первого прерывания в sim_instr main loop
- **Б:** Эмуляция «пультового старта» СВЯЗЬ7
- **В:** Вызов УСТРП из init/boot
- **Г:** Модификация ОС (hardcode MPRP)
- **А+Г:** Комбинация (текущий план)

- Начало подвала: `КОНЕЦ ЗАДАЧИ` или `СБО` (не `5555`!)

### 2026-09-24 (модуль ЭК7 — пользовательский дешифратор Э50133)

**Источники:** `re-dispak/26.02.2025-117А/ek7.be`, `re-dispak/26.02.2025-117А/svyaz7.be`

**Архитектура загрузки СВЯЗЬ7 через пользовательский `Э50 '133'`:**

```
Пользователь → Э50 '133' → BESM-6 (PC=0550, M[14]=133)
    → ЭК7.Э133 (ek7.be:18-29) → СВЯЗЬ7.Э50133 (svyaz7.be:873-921)
```

**Модуль ЭК7** (`ek7.be`, СТАРТ '11400'):
- Экспортирует: `Э133`, `ИЗСВ7` (строка 324)
- Импортирует из СВЯЗЬ7: `СВЯЗЬ7`, `Э50133` (строка 316)
- `∧К71 УСТВ 1` — признак К-71 (строка7)
- **Обработчик Э133** (строки 18-29):
  1. Читает `базсв7` — если ≠ 0, прыгает на Э133А (СВЯЗЬ7 уже в памяти)
  2. Если = 0: `ТБУФ` → выделение физ. страницы → `ФИЗОБМ` → физическое сопряжение
  3. Уход в `Э50133-СВЯЗЬ7` (пб по базовому адресу)

**Ключевой комментарий** (svyaz7.be:27-28):
```
*** !ПРИ ВЫЗ. Э50 '133' НЕ ЗАГР.
* ЗАГР. ПРИ УСТ. НАПР. КРК=0
```
→ Э50133 **НЕ загружает** модуль СВЯЗЬ7! Заголовок СВЯЗЬ7 (строки 30-148) — это блок определения типа оборудования, подключённого через ДКС, а не загрузчик.

**Реальный путь загрузки СВЯЗЬ7:**
1. `обдкс3` (svyaz7.be:63) проверяет `туsаб+18`
2. Если = 0 → `бинот7` (svyaz7.be:140-148): `ШКСВН |= E24 → пб ВИСП16`
3. `ВИСП16` (ДИСП70) — планировщик видит E24 в ШКСВН → подкачивает ИПЗ СВЯЗЬ7 с диска (зона 0677)

**Альтернативный путь** (vnimanije.txt):
- `ПРП6 → свядкс → загруз → нстдкс`
- `загруз`: E24 в ШГ, `аивсв7` в `ТУС-1+'31'`
- `нстдкс`: `ФИЗОБМ`, копирование векторов из `УХОДЫ`

### 2026-09-24 (биты 1-3 информационного слова Э50133)

**Биты 1-3 информационного слова = номер направления КРК** (0-7).

**Формирование в тесте** (test_sis_k71.txt:57-62):
```
СТАРТ2: *65,1       → А = ТР1
        ATX,ТР1     → сохраняем
        ASN,64+24   → сдвиг вправо 24: биты 25-27 ТР1 → биты 1-3
        AAX,=7      → маска бит 1-3 (номер направления)
        AOX,=7701 0000 4000 0000  → наложение на базовое слово
        *50,УС      → Э50 '133'
```

**Чтение в ОС:**

| Где | Строка | Код | Что извлекает |
|-----|--------|-----|---------------|
| СВЯЗЬ7 Э50133 | svyaz7.be:892-894 | `сч(М3); и П7; уи М5` | Биты 1-3 → М5 = номер направления КРК |
| СВЯЗЬ7 Э50133 | svyaz7.be:877-879 | `сч(М3); сда 64+6; и П77; по э133б` | Биты 7-12 → подфункция экстракода (0=стандартный) |
| СВЯЗЬ7 Э50133 | svyaz7.be:897-902 | `сч(М3); и Е36` | Бит 36 → только при М5=3 |
| ЭК7 ИЗСВ7 | ek7.be:36-40 | `сч0(М3); сда 64-12; счмр; и П7; уи М15` | Биты 1-3 → номер подфункции трассировки |

**Влияние бит 1-3 (М5 = номер направления):**
1. Индекс в таблицу `D47133[М5]` → маска М17 (svyaz7.be:903-905)
2. `E8(М17)` — проверка/установка бита МПРП для данного направления (svyaz7.be:970-975)
3. `УВВ '4034'` + `E8(М17)` — проверка/сброс бита ПРП через УВВ '30' (svyaz7.be:979-989)
4. Если М5 = 3 → дополнительная обработка через Е36 и D47133 (строка 897-902)

**Таблица D47133** (svyaz7.be:1306-1313) — маппинг направления → маска:
```
[0]=0, [1]=E1, [2]=E2, [3]=E2, [4]=E3, [5]=E2, [6]=E2, [7]=E2
```

**ПРП-обработчики** (svyaz7.be:1212-1224):
```
ПРП8 → М17=0, ПРП7 → М17=1, ПРП6 → М17=2, ПРП5 → М17=3
```

**Важно:** `Э50133` — это **процедура обмена** с ДКС (не загрузчик). Полный модуль СВЯЗЬ7 загружается через `ВИСП16` (планировщик) при `E24` в `ШКСВН`.

## Правила файлов БЕМШ / Монитор-80

### Синтаксис Монитора-80 (после `end$$$`)
- `*` + ровно 5 пробелов = **комментарий** (как в Фортране: `*     текст`)
- `*execute` — команда Монитора: выполнить загруженную программу
- `*end file` — команда Монитора: конец файла ввода
- `*libra`, `*call`, `*super`, `*assem`, `*read` — другие команды Монитора-80
- **Важно:** `*     execute` (5 пробелов) = комментарий, а `*execute` = команда!

## Структура подвала АЦПУ (правило разбора)

```
  КОНЕЦ ЗАДАЧИ   +mantissa⏨exp    hex
                 ^^^^^^^^^^^^^^^^  ^^^^^^^^^^^^^^^^
                 СУМАТОР (СМ)      РЕГИСТР МЛАДШИХ РАЗРЯДОВ (РМР)
  АП   Э     РК    И1    И2  ... КРА  ЗПСЧ
  (значения регистров)
```

- `+mantissa⏨exp` после `КОНЕЦ ЗАДАЧИ` = **значение сумматора (СМ)** на момент СТОПа
- `hex` рядом = **регистр младших разрядов (РМР)**
- `АП` = адрес программы (instruction counter), **НЕ** аккумулятор
- `S= XXXX` — статус задачи ОС, **НЕ** сумматор
- Шифр задачи в строке `41991...` (БЕЗ переопределения системой)
- При анализе подвала: искать по шифру запускаемой задачи
