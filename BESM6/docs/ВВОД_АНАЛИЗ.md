## 1. Структура входного файла (паспорт задачи)

Входной файл (колода перфокарт/перфолента) для ОС ДИСПАК состоит
из трёх частей: **паспорт задачи → тело задачи → конец файла**.

### 1.1. Паспорт задачи

Паспорт содержит директивы ресурсов, разделяемые символом `^`
(степень числа). Допустимо несколько паспортных строк;
каждая завершается `^`.

```
ШИФР 419999 ЗС5^          ← шифр задачи + категория
ОЗУ 32^                    ← страницы ОЗУ (в листах по 512 слов)
ТРА 100^                   ← тракты на барабане
АЦП 64^                    ← метры бумаги АЦПУ
ЛЕН 41(2048)^              ← лента: номер 41, шифр 2048
ДИС 67(2048)^              ← диск: номер 67, шифр 2048
ДИС 67(Siprod)^            ← диск с текстовым шифром
ТЕЛЕ^                      ← интерактивный режим
ВХО 70000^                 ← начальный адрес входа
ВРЕ 220^                   ← лимит времени (в секундах)
РОСП 0^                    ← роспись (для модулей ОС)
```

#### Обязательные директивы

| Директива | Формат | Описание |
|-----------|--------|----------|
| `ШИФР` | `ШИФР NNNNNN [ЗСN]^` | Идентификатор задачи (6 цифр). ЗС — категория |
| `ОЗУ` | `ОЗУ N^` | Число страниц ОЗУ (до 32, каждая = 512 слов) |

#### Опциональные директивы

| Директива | Формат | Описание |
|-----------|--------|----------|
| `АЦП` | `АЦП N^` | Метры бумаги (по умолчанию 7) |
| `ТРА` | `ТРА N^` | Тракты на барабане |
| `ЛЕН` | `ЛЕН NN(XXXX)^` | Магнитная лента: номер и шифр |
| `ДИС` | `ДИС NN(XXXX)^` | Магнитный диск: номер и шифр |
| `ТЕЛЕ` | `ТЕЛЕ^` | Интерактивный режим (вывод на ТТ) |
| `ВХО` | `ВХО N^` | Адрес входа в программу |
| `ВРЕ` | `ВРЕ N^` | Лимит времени (в секундах) |
| `РОСП` | `РОСП 0^` | Роспись (для резидентов) |

> **Важно:** Символ `^` — обязательный разделитель.
> Без него — «НЕТ КОНЦА ВВОДА».

#### Категории задач (ЗС)

| Категория | Описание |
|-----------|----------|
| ЗС1 | Наивысший приоритет |
| ЗС2 | Высокий приоритет |
| ЗС3 | Средний приоритет |
| ЗС4 | Обычный приоритет |
| ЗС5 | Низкий приоритет (наиболее часто) |
| ЗС6 | Наименьший приоритет |
| ЗС7 | Служебный |

### 1.2. Диспетчерское начало (ДН)

После паспорта идёт маркер начала данных для транслятора.
Существует два варианта:

```
EEВ1А3    ← смешанный латиница/кириллица (стандартный)
ЕЕВ1А3    ← чистая кириллица
```

### 1.3. Конец файла

```
``````    ← 5 обратных кавычек (терминатор данных)
ЕКОНЕЦ    ← альтернативный конец
```

Для задач с `*EXECUTE`:
```
*EXECUTE
*END FILE
``````
ЕКОНЕЦ
```

## 2. Директивы компиляторов (БЕМШ)

Директивы начинаются с `*` и идут после `EEВ1А3`.

### 2.1. Универсальные директивы

| Директива | Описание |
|-----------|----------|
| `*NAME [ИМЯ]` | Имя модуля (обязательна для трансляции) |
| `*CALL МОДУЛЬ` | Вызов модуля из библиотеки |
| `*SUPER` | Листинг МАДЛЕН в одну колонку (не супервизор!) |
| `*ASSEMBLER` | Трансляция БЕМШ-ассемблером |
| `*FULL LIST` | Полный листинг (с исходным текстом) |
| `*NO LOAD LIST` | Отключение листинга загрузчика |
| `*EXECUTE` | Начало блока исполнения |
| `*END FILE` | Конец файла задачи |
| `*LIBRA:N` | Пакет библиотеки (N = номер пакета) |
| `*RED` | Чтение из МЛ |
| `*FTN` | Трансляция Fortran |
| `*DTRAN(ИМЯ)` | Вызов транслятора DTRAN |
| `*PERSO:N` | Персональная настройка |
| `*EDIT` | Включение редактора |

### 2.2. Порядок директив

**МАДЛЕН-задача (с DTRAN):**
```
ШИФР 419999 ЗС5^
ОЗУ 32^ТРА 100^АЦП 64^
EEВ1А3
*NAME MADLEN
*SUPER
*ASSEMBLER
*FULL LIST
<исходный текст>
*EXECUTE
*END FILE
``````
ЕКОНЕЦ
```

**Без DTRAN (прямое исполнение):**
```
...
*CALL DTRAN(TEST)
*LIBRA:2
*EXECUTE
*END FILE
``````
ЕКОНЕЦ
```

**Fortran-Dubna:**
```
ЕЕВ1А3
*NAME PRIME NUMBERS
*CALL YESMEMORY
*FTN
      PROGRAM MAIN
      ...
      END
*EXECUTE
*END FILE
``````
ЕКОНЕЦ
```

### 2.3. Символ ^ (степень числа)

**КРИТИЧЕСКИ ВАЖНО:** `^` используется ТОЛЬКО как разделитель
паспорта. В исходном коде НЕ используется.
Степень обозначается символом `↑`.

## 3. Процедура ввода в эмуляторе simh

### 3.1. Запуск эмулятора

**КРИТИЧЕСКИ ВАЖНО:** Использовать ini-файл из OSZAGR!

```bash
cd /home/azizz/Yandex.Disk/simh/BESM6/OSZAGR
/home/azizz/Yandex.Disk/simh/BIN/besm6 dispak.ini
```

или через tmux:
```bash
tmux new-session -d -s besm6 \
  'cd /home/azizz/Yandex.Disk/simh/BESM6/OSZAGR && \
   /home/azizz/Yandex.Disk/simh/BIN/besm6 dispak.ini'
```

### 3.1а. Перезапуск ОС без перезапуска tmux

Если ОС зависла или нужна чистая загрузка — **не нужно** убивать tmux-сессию.
В приглашении `sim>` выполнить:

```
sim> do dispak.ini
```

Это перезагрузит ОС из ini-файла (все устройства переинициализируются).
Если в каталоге несколько `.ini` — можно `do *.ini` (SIMH выполнит первый
найденный) или указать конкретный файл.

> **Важно:** после `do *.ini` ОС загружается заново, все подключения
> (vu0, tty) сбрасываются. Перед вводом задачи — повторить §3.2 (detach/at vu0/FS8).

### 3.2. Алгоритм ввода задачи

1. **Дождаться загрузки ОС:** строка вида:
   ```
   CM1П:00.00.ЭBM-3  ДATA:DD.MM.GG BPEMЯ:HH.MM.SS  000.00
   ```

2. **Остановить CPU:** `Ctrl+G` → приглашение `sim>`
   > **Важно:** Если CPU не остановлен (нет приглашения `sim>`), команда
   > введённая на терминале может быть неверно интерпретирована ОС.
   > Признак: на операторском терминале появляется **НШИФ** (команда
   > не была распознана). Решение: повторить `Ctrl+G`, убедиться в
   > приглашении `sim>`, затем повторить операцию.

3. **Отключить VU0** (если подключён в ini):
   ```
   detach vu0
   ```

4. **Подключить входной файл** (АБСОЛЮТНЫЙ путь!):
   ```
   at vu0 /home/azizz/Yandex.Disk/simh/BESM6/VVOD/input.txt
   ```

5. **Подать сигнал FS8** (начало чтения перфоленты):
   ```
   d 6 1
   d 5 10
   set cpu req
   go
   ```

6. **Дождаться завершения:**
   - «КОНЕЦ ЗАДАЧИ» + строка из пятерок
   - Или команда НОМ покажет `КЗ(ПК) ШИФР ВРЕМЯ M=КАТ`

### 3.3. Формат команд FS8

| Команда | Назначение |
|---------|------------|
| `d 6 1` | Регистр 6 = 1 (код ФС) |
| `d 5 10` | Регистр 5 = 10 (сигнал) |
| `set cpu req` | Запрос прерывания |
| `go` | Продолжить выполнение (синонимы: `cont`, `c`) |

> **Примечание:** В SIMH команды `go`, `cont` и `c` — **синонимы**,
> означают «продолжить выполнение». Ввод `go` после `set cpu req` и `cont`
> после остановки (Ctrl+G) — одно и то же действие.

### 3.4. Проверка статуса (команда НОМ)

НОМ вводится на консоли ОС (tty1) при работающем CPU.

```bash
printf 'НОМ\r' | tmux pipe-buffer -t besm6 -
```

**Формат вывода:**
```
НОМ
 <ШИФР> <ПК>                    — задача в очереди
 КЗ(<ПК>) <ШИФР> <ВРЕМЯ> M=<КАТ> — задача завершена
```

### 3.4а. Проверка зависания терминала (команда ВЦП)

Команда **ВЦП** — выводит список задач, находящихся в решении (выполняются
или ждут). Полезна для определения, завис ли операторский терминал.

```bash
printf 'ВЦП\\r' | tmux pipe-buffer -t besm6 -
```

**Формат вывода:**
```
ВЦП
 <ШИФР> ...    — задача в решении
 ЗНЕТ          — задач нет (всё завершилось, терминал свободен)
```

**Как использовать:**
- Если приглашение `В0` не появляется после КЗ — ввести `ВЦП`.
- Ответ `ЗНЕТ` → терминал свободен, можно вводить следующее задание.
- Ответ с списком задач → система занята, подождать завершения.
- Если `ВЦП` тоже не отвечает → эмулятор завис (Ctrl+G, перезапуск).

### 3.5. Файлы логов

| Файл | Путь | Описание |
|------|------|----------|
| `log.txt` | `OSZAGR/log.txt` | Лог эмулятора |
| `output.txt` | `ACPU/output.txt` | Вывод prn0 |
| `output1.txt` | `ACPU/output1.txt` | Вывод prn1 |
| `punchcard.txt` | `UVU/punchcard.txt` | Буфер vu0 |

### 3.6. Ловушки

| Проблема | Решение |
|----------|---------|
| `Ctrl+G` не работает в fish | Запускать с `exec` или bash |
| SIMH не раскрывает `~` | Только абсолютные пути |
| `vu0` уже подключён в ini | `detach vu0` перед `at vu0` |
| Шифр `419999` = системный | Использовать уникальный |
| Нет вывода в prn0/prn1 | Нормально для задач с `ТЕЛЕ` |
| НШИФ на терминале | Эмулятор не остановлен → `Ctrl+G`, приглашение `sim>`, повторить |

## 4. Форматы входных файлов для компиляторов

### 4.1. МАДЛЕН (БЕМШ-ассемблер)

**Формат строки МАДЛЕН:**
```
 [МЕТКА]  , ОПЕРАНД_1 , ОПЕРАНД_2 [, КОММЕНТАРИЙ]
```

**Основные команды:**

| Команда | Описание |
|---------|----------|
| `СТАРТ2 : , *65 ,1` | Метка + команда тумблерного регистра |
| `, ITA ,` | Аккумулятор → индекс-регистр |
| `, XTA ,NPR` | Загрузка из ячейки в СМ |
| `, ATX ,NPR` | Запись из СМ в ячейку |
| `, UJ ,МЕТКА` | Безусловный переход |
| `, U1A ,МЕТКА` | Переход если СМ ≠ 0 |
| `, UZA ,МЕТКА` | Переход если СМ = 0 |
| `, AAX ,МАСКА` | Логическое И |
| `, AOX ,МАСКА` | Логическое ИЛИ |
| `, AEX ,МАСКА` | Исключающее ИЛИ |
| `, VJM ,ПРОЦ` | Вызов подпрограммы (ИР15 = адрес возврата) |
| `, VTM ,N(МР)` | Установка индекс-регистра |
| `, VLM ,МЕТКА` | Итерационный переход (ИР > 0) |
| `, ASN ,64+N` | Арифметический сдвиг влево на N |
| `, ARX ,К` | Арифметическое сложение |
| `, CALL,PRINT8` | Вызов системной подпрограммы |
| `, ITS ,N` | Передача ИРН в СМ |
| `, END ,` | Конец модуля |

**Директивы данных:**

| Директива | Описание |
|-----------|----------|
| `BSS [N]` | Выделить N слов памяти |
| `LOG ,N` | Логическая константа (восьмеричная) |
| `ISO ,NHТЕКСТ` | Текст в кодировке ISO |
| `CONT,NHТЕКСТ` | Продолжение текста |
| `EQU ,N` | Эквивалент (значение метке) |
| `КОНД` | Константа |

## 5. Формат листинга (АРАП)

### 5.1. Заголовок

```
АРАП ВАР.04/78
------------------------------------------------------------------
    М О Н И Т О Р-8 0  (3.7)   25.09.84*
```

### 5.2. Шапка полей

```
ОШИБКИ  НПК  СВОБ ПЕРЕМ АДРЕС КОМАНДА   А ИСП N ГЕН N ИСХ МЕТКА ОПЕРАЦИЯ ОПЕРАНД  КОММЕНТАРИЙ
```

### 5.3. Описание полей

| Поле | Описание |
|------|----------|
| ОШИБКИ | Количество ошибок трансляции |
| НПК | Номер перфокарты (или 0) |
| СВОБ | Служебное поле размещения |
| ПЕРЕМ | Информация о перемещении (`+` = положит.) |
| АДРЕС | Адрес размещения (восьмеричный) |
| КОМАНДА | Содержимое ячейки (КОП + адрес) |
| А ИСП | Исполнительный адрес |
| N ГЕН | Номер строки генерируемого листинга |
| N ИСХ | Номер строки исходного файла |
| МЕТКА | Определённая метка |
| ОПЕРАЦИЯ | Мнемоника команды или директивы |
| ОПЕРАНД | Операнд(ы) |
| КОММЕНТАРИЙ | Текст комментария |

### 5.4. Типовые строки

**Кодовая строка:**
```
002007011 0333           , ААХ ,Е25Р    .НАЛАД. ТЕСТ
```
Адрес: 07011, команда: 0333, операнд: Е25Р

**Строка с перемещением:**
```
+ 0126  76167 00 010 0000  0280 0198  СЧ  НУСВУ
```

### 5.5. Сводная таблица (CAT)
В конце листинга — перекрёстные ссылки:
```
ТЕСТООП  Е 01000   РLСLО*ID Е 01455   ISО/GОSТ   01523
РRОGRАМ  Е 01000   АSАVЕНL  Е 01463   СВОБОД   01572
```

### 5.6. Завершение трансляции

**Успешная трансляция:**
```
ЧИСЛО ОШИБОК=0. МАКС СЕРЬЕЗН=0.
```

**С ошибками:**
```
ЧИСЛО ОШИБОК=3. МАКС СЕРЬЕЗН=2.
```

## 6. Анализ результатов выполнения

### 6.1. Подвал задачи

```
КОНЕЦ ЗАДАЧИ  +000000000000...
  АП   Э     РК    И1    И2  ... КРА  ЗПСЧ
ДАТА РЕШ. ВЕРСИЯ ...
 ОС ДИСПАК ...
*АЦПУ-0  ЭВМ-3  HH.MM.SS*
*******************************************************************
5555555555555555555555555555555555555555555555555555555555555555555
```

Абсолютные маркеры конца:
- Строка из звёздочек (`*`)
- Строка из пятерок (`555555...`)

### 6.2. Состояние регистров

```
  АП   Э     РК    И1    И2    И3    И4    И5
00020 00020 00007 01116 74030 76031 06146 00000
```

| Поле | Описание |
|------|----------|
| АП | Адрес последней команды |
| Э  | Слово состояния (режимы) |
| РК | Регистр команд |
| И1-И17 | Индекс-регистры |
| КРА | Контроль адреса |
| ЗПСЧ | Счётчик запрета проверки |

### 6.3. Строка СБО (аварийный останов)

```
 СБО,ВВЕДИ ПО ИНС  +000000000000...  0000000000000000
```
Причины: неверный адрес, ошибка защиты, деление на ноль.

## 8. Типовые ошибки и их устранение

### 8.1. «НЕТ КОНЦА ВВОДА»

**Причина:** Нет `^` в паспорте или нет `ЕКОНЕЦ`.
**Решение:** Проверить `^` в конце каждой строки паспорта
и `ЕКОНЕЦ` / `````` в конце файла.

### 8.2. «НЕОПР ИНДЕКС» на М3/М7

**Причина:** Индекс-регистры не объявлены.
**Решение:** Добавить в конец модуля:
```
 м3 экв 3
 м7 экв 7
```

### 8.3. «ТИП КОНСТ»

**Причина:** Литерал `=ИМЯ` для метки (допустимо только
для числовых констант) или символы UTF-8 в комментарии.
**Решение:** Для меток — `СЧ ИМЯ`; убрать кириллицу
из комментариев.

### 8.4. «ИМЯ IS ABSENT»

**Причина:** Модуль не найден в библиотеке.
**Решение:** Проверить `*CALL DTRAN(ИМЯ)` — имя должно
совпадать с меткой СТАРТ, и `*LIBRA:N`.

### 8.5. «СБО,ВВЕДИ ПО ИНС»

**Причина:** Аварийный останов.
**Решение:** Проверить `ВХО N^` и `ОЗУ N^` в паспорте.

### 8.6. Нет вывода в output.txt

**Причина:** Задача с `ТЕЛЕ` — вывод на терминал.
**Решение:** Проверять через команду НОМ.

## 10. Алгоритм запуска теста контактов ДКС (test_sis_k71.txt)

Тест `test_sis_k71.txt` (МАДЛЕН) проверяет ОЗУ ДКС через команды
132 (Z13, запись) и 032 (Z03, чтение). Диапазон адресов: 10₈–67777₈.
Описание ниже извлечено из комментариев исходного текста теста.

### 10.1. Паспорт задачи (входной файл)

```
ШИФР 419999 ЗС5^           ← шифр + категория (ЗС5 = низкий приоритет)
ОЗУ 32^ТРА 100^АЦП 64^ЛЕН 41(2048)^
```

### 10.2. Управление тестом (тумблерные регистры)

Тест считывает два тумблерных регистра через команды `*65`:

| Регистр | команда | Содержимое |
|---------|---------|-----------|
| ТР1 | `*65 1` | Адрес и направление для наладочного теста |
| ТР4 | `*65 4` | Управляющие биты (режим работы) |

**Биты ТР4 (управление режимом):**

| Бит | Маска восьм. | Имя | Действие |
|-----|-------------|-----|----------|
| 22 | `10 000 000` | Е22Р | Только ЧТЕНИЕ (ЦЧТ): тест читает без записи |
| 23 | `20 000 000` | Е23Р | Только ЗАПИСЬ (ЦЗП): тест пишет без чтения |
| 24 | `40 000 000` | Е24Р | **ВКЛЮЧЁН** → тест работает **без пауз** (непрерывный режим) |
| 25 | `100 000 000` | Е25Р | НАЛАДочный режим: формируется адрес для каждого прохода |
| 26 | `200 000 000` | Е26Р | **ОСТОНОВКА при ошибке** (СТОП вместо продолжения) |

**Содержимое ТР1:**

| Разряды | Имя | Действие |
|---------|-----|----------|
| 46-48 (старшие) | Направление КРК | Номер направления (0-7) для экстракода `*50 УС` (УСТ. N НАПРАВЛ) |
| 24 | Е24Р | **ВЫБРОС** → тест печатает результаты и выходит (`SJ` в ОС) |

> ТР1 **не является** просто флагом — он задаёт **направление КРК**
> (КАДОПАМ-КРК), через которое будет выполняться обмен данными.
> Экстракод `*50 УС` настраивает аппаратуру ДКС на нужное направление.

> **ВАЖНО:** Е24Р проверяется в **двух разных регистрах**:
> - В **ТР4** (строка 34-36 исходника): `XTA ТР4 / AAX Е24Р / UZA ПАУЗА` —
>   если Е24Р=0 → ПАУЗА (экстракод `*50 7 700B`), тест не выполняет тесты;
>   если Е24Р=1 → тест непрерывно выполняет все 8 тестов.
> - В **ТР1** (строка 31-33): `XTA ТР1 / AAX Е24Р / U1A ВЫБРОС` —
>   если Е24Р=1 → немедленный ВЫБРОС с распечаткой результатов.

**Режимы работы:**

| ТР4 Е24Р | ТР1 Е24Р | Поведение |
|----------|----------|-----------|
| 0 | 0 | ПАУЗА: тест читает регистры → пауза → повтор. Тесты НЕ выполняются |
| 1 | 0 | НЕПРЕРЫВНЫЙ: тест выполняет все 8 тестов в цикле, без пауз |
| 0 | 1 | ВЫБРОС: тест сразу выходит с распечаткой (проходов=0) |
| 1 | 1 | ВЫБРОС: тест выходит при первом проходе СТАРТ → проверка ТР1 → ВЫБРОС |

**Режим по умолчанию** (без установки бит — оба регистра = 0):
- Тест работает в ПАУЗЕ, тесты НЕ выполняются. Нужно установить `d 4 040000000` для запуска.

### 10.3. Цикл тестирования (ПЕРЕКЛ)

Тест выполняется по таблице переключений ПЕРЕКЛ (8 тестов):

| № | Метка | Описание (из комментариев) |
|---|-------|---------------------------|
| 1 | Т1 | ЗП-ЧТ ПО АДР. НИЖ. ГР. — запись-чтение по адресу нижней группы |
| 2 | Т2 | ЗП-ЧТ АДР. В АДР. — запись-чтение адрес в адрес |
| 3 | Т3 | ЗП-ЧТ ВСЕ 1 — запись-чтение всех единиц |
| 4 | Т4 | ЗП-ЧТ ВСЕ 0 — запись-чтение всех нулей |
| 5 | Т5 | БЕГУЩАЯ 1 — бегущая единица |
| 6 | Т6 | БЕГУЩАЯ 0 — бегущий ноль |
| 7 | Т7 | ЦИКЛ СЛ. КОН.=113 — циклическая запись константой 113₈ |
| 8 | СЧЕТ | УВЕЛИЧ. СЧЕТ ПРОХОД — увеличение счётчика, возврат к Т1 |

Каждый тест пишет/читает блок 200 слов по адресу 20000₈ в kadopam_mem.
После 8 тестов — один полный проход; счётчик проходов увеличивается.

### 10.4. Точки останова

| Условие | Механизм | Что происходит |
|---------|----------|----------------|
| ТР1 Е24Р=1 | `ВЫБРОС` (стр.86-104) | Печать «ТЕСТ ВЫВЕДЕН ИЗ РЕШЕНИЯ» + кол-во проходов + ошибок → `SJ` (возврат в ОС) |
| ТР4 Е24Р=0 | `ПАУЗА` (стр.105-107) | `*50 7 700B` (экстракод — пауза планировщика) → `UJ СТАРТ` (продолжение) |
| ТР4 Е24Р=1 | Нет паузы | Тест непрерывно выполняет все 8 тестов в цикле |
| Е26Р=1 + ошибка | `СТОП` (стр.308) | `2, Z33` — мёртвый стоп машины (авост) |
| Е26Р=0 + ошибка | `ME5/ME2` (стр.300-307) | Печать ошибки → продолжение цикла |

**Порядок проверок в СТАРТ** (строки 25-42):
1. `*65 1` → чтение ТР1, сравнение с сохранённым → если изменился → `СТАРТ2` (перенастройка)
2. `*65 4` → чтение ТР4
3. `XTA ТР1 / AAX Е24Р / U1A ВЫБРОС` → если ТР1 Е24Р=1 → **немедленный ВЫБРОС**
4. `XTA ТР4 / AAX Е24Р / UZA ПАУЗА` → если ТР4 Е24Р=0 → **ПАУЗА** (тесты не выполняются)
5. Если ТР4 Е24Р=1 → продолжение к выбору теста

### 10.5. Запуск

```bash
# Строго по §3.2:
# 1. Убедиться что ОС загружена (CM1П в tmux capture-pane)
# 2. Остановить CPU (Ctrl+G — достоверно работает через tmux):
tmux send-keys -t besm6 C-g
sleep 2
# 3-4. Подключить тест:
tmux send-keys -t besm6 'detach vu0' Enter
sleep 1
tmux send-keys -t besm6 'at vu0 /home/azizz/Yandex.Disk/simh/BESM6/VVOD/test_sis_k71.txt' Enter
sleep 1
# 5. Установить ТР4: Е24Р=040000000 (непрерывный режим, без пазу)
tmux send-keys -t besm6 'd 4 040000000' Enter
sleep 0.5
# 6. FS8 (сигнал ввода):
tmux send-keys -t besm6 'd 6 1' Enter
sleep 0.5
tmux send-keys -t besm6 'd 5 10' Enter
sleep 0.5
tmux send-keys -t besm6 'set cpu req' Enter
sleep 0.5
tmux send-keys -t besm6 'go' Enter
```

> **Примечание:** Установка ТР4 Е24Р=1 критична! Без неё тест работает
> в режиме ПАУЗА (`*50 7 700B`), тесты НЕ выполняются.
> Если нужен **одиночный проход** с распечаткой результанов,
> добавить также `d 1 040000000` (ТР1 Е24Р=1 → ВЫБРОС).
