# БЕНСОН-501: формат кадра и команды (аналог NASA)

Статус: **аналог**, а не доказанный протокол НИТИ или БЭСМ-6. Каждая строка
вывода помечается `[аналог NASA, БЕНСОН-501]`.

## 1. Что именно доказано, а что нет

Первичный источник: NASA Technical Memorandum 76182, сентябрь 1980,
"Linking of the \"BENSON\" Graph-Plotter with the \"ELEKTRONIKA-100I\" Computer",
I. Ye. Val'tts, N. Ya. Nikolaev, M. V. Popov, V. A. Soglasnov. Перевод отчёта
Института космических исследований АН СССР Pr-448 (1978), стр. 1-17.
NTRS ID `19810010147`,
[PDF](https://ntrs.nasa.gov/api/citations/19810010147/downloads/19810010147.pdf).

Из отчёта следует: графопостроитель BENSON-FRANCE модели 501 имеет поле
50 x 75 см, шаговые двигатели, дискретность 0.1 мм; в автоматическом режиме
управление идёт по пяти шинам `+X`, `-X`, `+Y`, `-Y`, `Pen Control`; импульс
+5 В перемещает перо на один шаг 0.1 мм. Шесть команд внешнего устройства
(table 2, стр. 7 PDF) перечислены ниже.

**Не найдено:** описание формата 16-разрядных элементов БЕНСОна периода НИТИ,
схема советской платы сопряжения с БЭСМ-6, разводка разъёма и электрические
параметры шин. NASA-отчёт описывает сопряжение с Электроникой-1001, поэтому
перенос его кодов на БЭСМ-6 остаётся OSINT-моделью. Никакие утверждения о
"протоколе НИТИ", "подлинном формате команд БЕНСОНа" или ASTM-совпадении
здесь не делаются; NASA и ASTM не endorsируют эту реализацию. Использованы
только короткие цитаты и числовые факты отчёта, исходный код или защищённые
материалы не копируются.

Связанный разбор: [`re-niti-graph/docs/BENSON-COMMAND-FORMAT.md`](../../../re-niti-graph/docs/BENSON-COMMAND-FORMAT.md).

## 2. Формат кадра

Кадр состоит из 64 слов по 48 бит. `plot.dat` пишет каждое слово как восемь
шестибитных октальных групп (по две октальные цифры на группу, с ведущим
пробелом), 64 строки на кадр:

```c
for (j = 7; j >= 0; --j)
        fprintf(plot, "%02o ", (unsigned)((v >> (j * 6)) & 077));
fputc('\n', plot);
```

Контракт кадра (Fortran `PDEV` -> ЭК 01210/01211 -> декодер):

| Слово | Содержание |
|---:|---|
| 0 | X в шагах 0.1 мм, младшие 24 бита, знак расширяется по биту 23 |
| 1 | Y в шагах 0.1 мм, там же |
| 2 | состояние пера: 0 поднято, ненулевое опущено |
| 3..63 | нулевое значение; FOREX оставляет в них тег типа `0xd00000`, который декодер игнорирует |

FOREX 4.12 хранит `INTEGER` с тегом `0xd00000` в старших 24 битах; декодер
берёт младшие 24 бита (`du_coord_value`) и расширяет знак по биту 23.
Ограничения модели: `0 <= X <= 5000`, `0 <= Y <= 7500`, шаг 0.1 мм.

Эталонный кадр C1-line (дека `re-niti-graph/verify/C1-line.b6`): две точки
`MOVE/PLOT (10,10)` и `(110,110)`. В восьмеричных группах:

```
64 00 00 00 00 00 00 12   word0: X = 10 (тег + 012)
64 00 00 00 00 00 00 12   word1: Y = 10
64 00 00 00 00 00 00 01   word2: перо опущено
64 00 00 00 00 00 00 00   words 3..63: значение 0 с тегом типа
...
```

Второй кадр отличается только словами 0 и 1: `64 00 00 00 00 00 01 56`
(`0156` = 110 decimal).

## 3. Команды

| Код (восьм.) | Строка | Действие |
|---:|---|---|
| 06501 | `6501 +Y` | шаг +Y |
| 06502 | `6502 +X` | шаг +X |
| 06504 | `6504 -Y` | шаг -Y |
| 06511 | `6511 UP` | перо вверх |
| 06512 | `6512 DOWN` | перо вниз |
| 06514 | `6514 -X` | шаг -X |

Ведущий ноль в записи кода (`06502`) это то же число, что `6502`; `benson.out`
использует формат `%03o`, то есть четыре цифры без ведущего нуля.

Порядок команд на кадр: смена состояния пера, если она нужна, затем все шаги
X, все шаги Y, затем `UP`, затем фиктивные `+X` и `-X` с поднятым пером.
Последние два шага нужны, чтобы проверенный рендер `plotter.cpp` вывел
последний path: он сбрасывает накопленную линию только при движении с
поднятым пером. Положение после пары шагов восстанавливается.

Формат строки `benson.out`:

```
%03o %s X=%05d Y=%05d [аналог NASA, БЕНСОН-501]\n
```

Пример: `6502 +X X=00001 Y=00000 [аналог NASA, БЕНСОН-501]`.

## 4. Рендер

`besm6_gp_decoder.c` не содержит SVG-кода. Байты команд через
`plotter_bridge.cpp` попадают в проверенный MIT-бэкенд Serge Vakulenko
`plotter.cpp` (канонический источник `besm6-new/dubna/plotter.*`,
[аналог Calcomp/Tektronix/Watanabe]). При завершении `benson_finish()`
вызывает `dubna_plot_finish(0)`, переименовывает `calcomp.svg` в `benson.svg`
и удаляет промежуточный `calcomp.out`. `benson.out` пишется только при
включённом флаге (`set gp plot=on` или `BESM6_DUBNA_PLOT_KEEP`).
