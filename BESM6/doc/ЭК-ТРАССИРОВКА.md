# Трассировка экстракодов ЭК 050 1200..1237 в ДИСПАК

Памятка по отладке прохода экстракода графопостроителя через полный
ДИСПАК в simh. Механизм важен для РПГ и БЕНСОНа: оба вызываются ЭК 050
1210/1211, но проходят через гостевой диспетчер ОС, а не через хост.

## 1. Два уровня трассировки simh

### Уровень CPU (вход в экстракод)

В `besm6_cpu.c`, метка `stop_as_extracode`, при `opcode == 050` и
`Aex` в диапазоне 01200..01237 печатается в `sim_log`:

```
*** TRACE GP-EK050 PC=%05o Aex=%05o ACC=%016o M3=%05o M16=%05o
```

Включение: `GPSTAR_CPU_DEBUG=1` в `run-gp-star.py` добавляет в `simh.ini`
строки `set cpu debug` и `set console log=<work>/cpu.log`.

Пример реальной строки из прогона с дека `gp-star-key3.b6`
(ключ `3,VTM,71717B` в PDEV):

```
*** TRACE GP-EK050 PC=01244 Aex=01210 ACC=0000000000001141 M3=71717 M16=01127
```

То есть на входе в CPU всё корректно: подфункция 01210, ключ 71717₈
в М3, в ACC адрес кадра.

### Уровень гостевого кода (диспетчер ОС)

`debug.log` (включён `set debug`) содержит пошаговую трассу guest:
адрес, полуслово команды, запись в память и значение регистров:
`01243 R: 00 050 1210 э50 1210 = 1210`. Это основной источник для
разбора цепочки disp70/vzu/boek1. `cpu.log` при `set cpu debug` пишет
только чтения MMU, поэтому для гостевого управления нужен `debug.log`.

## 2. Прослеженная цепочка ЭК 050 1210

```
01243 R: э50 1210            вход из задачи, ACC = адрес кадра
00550 L: зп 2213             Э50 → ВЗУ Э1
00550 R: пб 07053
07053 → 04750 → 04677 → 04704 → 06742 (ЭКЛИСТ)
06767 L: сч 116 → ACC=0100...0000 (бит 37 / признак ГП)
06767 R: пб 04442 → ТВ40
04442 → 16404 (БОЭК1.ВЫЗОВ)
16410: сч 44(16) → [72515] = 0002 0200 6107 7472   (слово 36 ИПЗ, поле вызова нерезидента)
16417: и 72050 → ACC=0 → по 04445 (ТИВ)
04445: зп 2217; сда 117; и 172; нтж 525
04455: сч 2075(16)=0 → зп 2075=4                    (ШЗН = номер нерезидента 4)
04457: уиа 3546(16) → ВИСП3 → 03643 → пв 17760
03546 → 04201 (БПУ) → 04311 (БВЗ) → 04344 (БВЗ32)
дальше переключение контекста на другую задачу (M3=00026)
```

**Точка обрыва:** ТРУБКА (`START 10000₈`, `rvs.src` зона 0413) ни разу
не исполнялась (`grep '^1000[0-7] [LR]:' debug.log` → 0 совпадений).
Нерезидент помечен в `ШЗН`, `ВИСП` активирован, но модуль не загружен:
после ТИВ идёт упрятывание текущей задачи и переключение контекста.

## 3. Что НЕ является ошибкой

- `КЗ(075)` / `ОЗ(075)` — число в скобках это **номер задачи на буфере
  ввода**, а не код авоста (`Dispak-operator-guide.md:2655`). Аналогично
  `КЗ(001)` в консоли — конец системной задачи 419919810623, а не нашей.
- `ОШ.ПАРАМ.АРХИВА`, `СМЕНИ ВЕРСИЮ АРХ`, `НЕТ ДУБЛЬ-ЗОНЫ`, `ОЗ(077)` —
  архивные сообщения, к вызову ГП отношения не имеют.
- Расхождение M16: трассировка CPU печатает `01127`, а в `debug.log`
  в момент чтения `СЧИ М16` стоит `01210`. Это разные моменты и разные
 использованием регистра; для анализа guest-пути важнее `debug.log`.

## 4. Раннер и флаги

`run-gp-star.py` 지원:

- `GPSTAR_DECK=<путь>` — подать альтернативную деку;
- `GPSTAR_CPU_DEBUG=1` — добавить `set cpu debug` + console log;
- ожидание **своего** ACPU-маркера `GРSТАR: 10 FRАМЕS DОNЕ` с collo
  ACPU-файлов перед каждой подачей (иначе `КЗ` системной задачи
  принимается за конец нашей).

## 5. Нижний уровень: ЭК работает без полного ДИСПАК

`re-niti-graph/verify/niti-lowlevel/run.sh` (6 дек, autonomous `dispak`)
все PASS, включая `t06-legacy-71717.b6` с `3,VTM,71717B` перед
`*50,1211`. `re-niti-graph/verify/native/` показывает родную библиотеку 22
через прослойку `PLOT` с ЭК 1210/1211. То есть сам ЭК и ключ рабочие;
проблема именно в activation нерезидента полным ДИСПАК.

## 6. Открытый вопрос

Почему `ВИСП` не загрузил нерезидента после `ТИВ → ШЗН=4`: нужна проверка
каталога нерезидентов на системном диске (md00) и кода возврата `ВЫЗОВА`.
Если конфигурация ГЕНС загрузочного диска не содержит разряд 36 (`ГП`),
ГЕНС не кладёт ТРУБКУ/ГП1 в каталог, и активация невозможна. Следующий
шаг - собрать загрузочный диск с `РПГ БЭСМ`/`РПГБ ДА` (см. `ГЕНС.md`)
и повторить трассировку.
