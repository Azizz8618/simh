## 1. Установлено прогонами на живом ДИСПАК (сводка)

1. **Экстракод вызова нерезидента ДУДКА — Э50 1216.** Цепочка:
   э50 1216 (задача) → вектор 0550 ВЗУ → ЭКЛИСТ (vzu.be:2139) →
   НАЙДУ (2173) → ТРУБ (2184: «сч Е37; пб ТВ40») → ТВ40 (disp70.be:2236)
   → БОЭК1.ВЫЗОВ → ТИВ → ШЗН → ВИСП15 → ВИСП → ТБУФ+ВИСП12 → ФИЗОБМ
   читает зону **0413** (ТРУБКА) → ТРУБКА загружена на 10000₈ →
   точка входа → Э5200 (пароль СОБР=71717₈ по 19-му слову ИПЗ) →
   .ДА1 → э1216 (trubka.be:358) → гпнити (678): слиа -8(М3) → индекс 6 →
   нерез (703): слиа -7(М3) → 077777₈ ≠ 0 → пио НЕ срабатывает →
   **или кусгп5 (400066₈) + или НОММБ1 → пб нафиз → ФИЗОБМ читает зону
   0576 с программного МБ → ДУДКА** (rvs.src:70: дудка нс011000 в зоне
   0576; ГП5 = ДУДКА, NATIVE-BLOCKED.md §13).
2. Рантайм-подтверждена загрузка ТРУБКА: после `TRACE GP-EK050
   Aex=01210` (с ключом М3=71717) ОС читает зону 0413 (`physobm
   @17753, zone = 0413`). Без ключа — авост ЗАПРЕЩ.ЭКСТРАКОД (код 36).
3. 1210 — вход в ТРУБКУ по КУС «пароль» 4070301400000₈ (зона 703
   системной МЛ), ДУДКУ не грузит. 1217 — ветка заг564 (зона 0564 =
   ПЛАН по rvs.src:44), тоже не ДУДКА.

## 2. Поток данных кадра (по исходникам re-dispak)

- **Кадр идёт через выводной поток задачи**: выводная информация
  попадает в зоны вывода на информационном МБ (НОММБ), каталог вывода —
  зона 0550 системного МД (`КУСВЫВ п'01И200'` disp70.be:827, КУС550
  dnepr.be:1809). Их читает `вдудку` (benson.be:133-149) по КУС из
  2-го слова ИПЗ (КУС = м17в'1'м2в'24', benson.be:25).
- ДУДКА берёт **два листа** буферов (ФИЗОБМ ×2, dudka.be:101,117),
  подменяет вектор обвнп1+30 на ЗАМЕНА (dudka.be:120-131), инициализирует
  БЕНСОН 9 словами через рег '34' (143-162), ставит маску 18Р
  (`сч E18; пв ТВ67`, 163-165), затем цикл G10054: вдудку читает
  очередную зону вывода → печшк3 раскладывает слова на 16-разрядные
  элементы (маски е16п1=0177777, D10310=017777, D10115=060000,
  D10114=01377) в кольцевой буфер ячсост (0330-0377) → УВВ '164'/'165'
  выдают байты (benson.be:72,80,266,270).
- **Прерывание 18Р — 2 раза на слово** (фазы D10156 0/1):
  ЗАМЕНА-обработчик (dudka.be:242-294) на каждом 18Р делает
  рег '34' ×6 слов + **рег '240' (чтение слова, dudka.be:265)**,
  продвигает счётчики D10155/D10114.
- **Завершение**: бит 48 во 2-м слове ИПЗ (конец выводного потока) →
  G10072 (dudka.be:199-212): счётчик кадров в 0-е слово ИПЗ, ТВ67А
  (гашение маски 18Р), рег '34' ×2 (сброс), возврат листов ТБУФ;
  ВЫХОД (214-228): восстановление вектора обвнп1+30 из СТАРОЕ.
- **Если 18Р не придёт** — бесконечный повтор вдудку (G10054),
  задача не завершается (что и наблюдалось в фазе B2: цикл 04440 →
  СТ175-тупик ОС).
- ЭК 50 1211 в гостевой ТРУБКЕ отсутствует (grep по trubka.be/
  disp70.be/vzu.be) — путь «кадр по адресу в СМ» существует только в
  пакетном эмуляторе dispak (extra.c). Гостевой путь данных —
  исключительно выводной поток → зоны МБ.

## 4. План доведения гостевого пути (патчи simh)

Минимальный набор для прогона «дека → ЭК 50 1216 → ДУДКА → БЕНСОН →
plot.dat/benson.svg» на живом ДИСПАК:

1. **cmd_033, case 04023** (и 04020-04022): вернуть статус «готов»
   (ACC = 0 или готовые разряды) вместо STOP_UNIMPLEMENTED.
2. **cmd_033, cases 0155/0164/0165/0166/04102**: развести на gp-устройство:
   - 0155 → no-op (вкл/выкл) с отладочной печатью;
   - 0164/0165 → приём младшего/старшего байта элемента (копить пару
     байтов в слово → в конвейер кадров gp, по 64 слова → benson_frame);
   - 0166 → ACC = «свободен» (0);
   - 04102 → ACC = готовность ГП (бит 13 или 9).
   Вариант проще: 0164/0165 писать в gp-поток напрямую (gp_data_write
   не подходит — это УВВ 0172/0173); добавить gp_byte_write(lo/hi).
3. **18Р по слову готовности**: поднимать 18Р не с каждого УВВ 0172,
   а когда ДУДКА выдал очередную пару байтов ('164'+'165') — т.е. по
   завершении слова из печшк3; либо сохранить «на каждое слово» и
   убедиться, что фазы D10156 совпадают.
4. **рег '240'**: возвращать слово, собранное из '164'/'165' (эхо
   устройства), продвигая счётчик — это и есть протокол ЗАМЕНА.
5. **Патч констант 01457/01460** в загрузчике теста (как run-gp-irq.py)
   — либо включить разряд 18 в ПОДПРГ при генерации диска.
6. **Throttle**: убедиться, что `set throttle 1m` принимается (проверить
   синтаксис `=` vs пробел), иначе НОМВ/печать ломаются на полной скорости.
7. **Дека**: ЭК 1216 + ключ 71717 в М3 (`3,VTM,71717B; *50,1216B`) +
   выводной поток с кадром (FORTRAN PRINT/метка вывода, либо прямой
   запрос зон) — данные должны попасть в зоны вывода МБ, которые
   читает вдудку.
