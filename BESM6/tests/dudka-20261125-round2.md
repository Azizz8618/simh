# СТАТУС: Э50 1216 + ДУДКА + ГП по схеме НИТИ — раунд 2 (25.11.2026)

## Сделано в этом раунде

### 1. Патчи simh — НИТИ-интерфейс БЕНСОН-501 (коммит a536f66, запушен)

**besm6_gp.c / besm6_gp.h** — новый НИТИ-контур:
- `gp_niti_control` — УВВ '155: бит 22 вкл/бит 24 выкл (benson.be:116,346);
- `gp_niti_byte` — УВВ '164(мл)/'165(ст): байты 16-битного элемента
  (benson.be:72,80,266,270); пара байтов = элемент → **18Р**
  (gp_raise_irq) + эхо для рег '240';
- `gp_data_read` в НИТИ-режиме — рег '240 возвращает элемент эхом
  (dudka.be:265) и собирает слово из 3 элементов (печшк3,
  benson.be:186-227); 64 слова → `gp_deliver_frame` → benson_frame
  → plot.dat / benson.out / benson.svg;
- `gp_niti_status` — УВВ '4023 (опрос ГП в ТРУБКЕ, trubka.be:106),
  '04164/'04165 (эхо байтов), '04166 (состояние);
- `gp_niti_ready13` — разряд 13 УВВ '4102 (готовность ГП).

**besm6_cpu.c cmd_033** — разводка адресов на НИТИ-контур при
включённом интерфейсе (gp_niti_active): '155, '164/'165, '4023,
'04164-'04166, бит 13 в '04102. Все адреса продолжают обслуживать
перфоратор, когда НИТИ выключен — регрессия не задета.

## НЕ доведено (точка продолжения)

Задание умирает на «--- (02000) instruction parity error» сразу
после старта МАДЛЕН-трансляции, до ЭК 50 1216. ЭК 1216 в этом
прогоне не выполнялся (GP-EK050 Aex=01216 в console.log нет).

Гипотезы для следующего шага (по убыванию вероятности):
1. **Диск 2048 = /home/z/my-project/disks/2048 не совпадает с томом
   МАДЛЕН**. В базовом ini (OSZAGR/dispak.ini) md41 указывал на
   2070/2094 и т.п.; рабочий стенд run-gp-star использует том 2048
   как копию NITI-диска (md45 = копия 2348!). В фазе A работала
   подача «лен 41(2048)» с ini, где md41 = локальный img-2048.
   Проверить: какой том в /home/z/my-project/disks/2048 (сравнить
   sha256 с дисками стенда), вернуть md41 = img-2048 как в
   trace_phase_a.py (фаза A проходила до ВЗУ/ТРУБКИ).
2. Parity error на 02000 — загрузчик деки пишет колоду с 02000;
   возможно, колода в UTF-8 с CRLF или содержит символы вне ГОСТ.
   t16-key-1216.b6 — из рабочей фазы B2, но тогда ini был другой.
3. Патч 01457/01460 в этом месте уже применён ОС-кодом заново
   (ячейки перезаписаны при инициализации задачи) — патчить надо
   ПОСЛЕ старта задания или не патчить вовсе (проверено: в этом
   прогоне РЕГ 037 идёт без остановки — маски уже живые).
