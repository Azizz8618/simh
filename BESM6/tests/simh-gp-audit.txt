# Аудит БЭСМ-6/SIMH: устройство GP (БЕНСОН-501) и диспетчер cmd_033 (субагент, 25.11.2026)

Источник: /home/z/my-project/repos/simh/BESM6/*. База анализа — текущий
коммит 77739441. Сокращённая выжимка полного отчёта субагента.

## 1. cmd_033 (команда 033 «увв») — besm6_cpu.c:623-913, switch (Aex & 04377)

| Aex | Строки | Действие |
|---|---|---|
| 034 | 686-691 | запись в МПРП: MPRP = ACC & 077777777 |
| 0154, 0155 | 735-741 | pi_control — перфоратор (двигатель/отбор) |
| 0160-0167 | 742-746 | pi_write — электромагниты перфоратора (0164/0165/0166 уходят СЮДА, не в ГП) |
| 0172, 0173 | 751-754 | gp_data_write(ACC) — единственный живой вход в GP |
| 01210-01217 | 755-758 | gp_extra — МЁРТВЫЙ КОД: Aex & 04377 для 01210 = 01010 → default → mg_ctl |
| 04020-04023 | 805-809 | STOP_UNIMPLEMENTED — УВВ '4023' (опрос состояния ГП) ОСТАНАВЛИВАЕТ симулятор |
| 04102 | 837-841 | ACC = READY2 (перфокарты; разряд 13 = PI2_START, не ГП) |
| 04160-04167 | 872-876 | pi_read — '166' читает мусор перфоратора |
| 04030/04031/04034 | 810-822 | ст. ПРП / READY / мл. ПРП |
| прочее | см. полный отчёт | (drum/disk/mg/printer/tty/vu/pi/consul/osa...) |

Требует супервизора (cpu.c:1390-1394, IS_SUPERVISOR). Чтение (Aex & 04000)
ставит логический режим АУ.

РЕГ ≠ УВВ: РЕГ '34' — команда 002, cpu.c:549-553 → gp_config_write
(НЕ МПРП; МПРП портит только УВВ 034). РЕГ '240' — cpu.c:595-598 →
gp_data_read. РЕГ '107' — cpu.c:565-585 (флаги RUU, безвредно).
РЕГ '036'/'037' — cpu.c:554-563 (МГРП / гашение ГРП; разряд 18 гасится).

## 2. Устройство GP — besm6_gp.c (384 строки)

- Состояние (56-74): gp_enabled (ТВ67), gp_ready, gp_phase (D10156),
  gp_word_count (D10155), gp_buf[64], gp_config[16], счётчики.
- MTAB (173-185): TV67 → MGRP |= MGRP_GP; TV67A; PLOT/NOPLOT; TESTIRQ →
  gp_raise_irq().
- gp_data_write (296-307, УВВ 0172/0173): слово в gp_buf[count++ % 64],
  gp_phase ^= 1, gp_raise_irq() НА КАЖДОЕ СЛОВО; при 64 словах →
  gp_deliver_frame().
- gp_deliver_frame (232-246): дозаполнение нулями, gp_raw_write (attach
  gp0 — сырой поток), benson_frame(gp_buf, 64) — декодер → plot.dat /
  benson.out / benson.svg.
- gp_data_read (279-288, РЕГ '240'): gp_buf[gp_read_idx++ % 64]; до
  первого кадра — нули.
- gp_config_write (265-276, РЕГ '34'): кольцевой буфер 16 слов, каждое
  6-е слово ставит gp_ready=1, ++gp_mask_loads. (По rukava.be:404,536 это
  маски ПРП/ГРП, не команды устройству.)
- gp_extra (317-384): 01210/01217 — выбор схемы (gp_ready=1); 01211 —
  кадр из 64 слов из memory[ACC & BITS(15)] + deliver; 01215 — ТВ67/
  ТВ67А/test-hook; 01216 — чтение/запись/гашение ячейки-вектора 04023
  (GP_VECTOR_CELL, besm6_defs.h:399-404). ВЕСЬ gp_extra — мёртвый код
  (см. маску 04377).
- Декодер besm6_gp_decoder.c: benson_frame (197-254) — word0=X, word1=Y,
  word2=перо; команды NASA 06501/06502/06504/06511/06512/06514 → SVG.
  Формат «аналог NASA», не НИТИ (gp_decoder.c:8-14).

## 3. Прерывание 18Р

- Подъём: gp_raise_irq (gp.c:249-254), GRP |= GRP_GP (BBIT(18),
  defs.h:399-400, «внутренний разряд, не ПРП»). Вызовы: gp_data_write
  (304), gp_extra (341, 358), set gp testirq (169).
- Захват CPU: cpu.c:2002-2008: !iintr && !правая && !PSW_INTR_DISABLE &&
  GRP & MGRP & GRP_GP → gp_trace_irq("GRP18 -> op_int_1 0500") и
  op_int_1() (cpu.c:1768-1784): PC = 0500, супервизор.
- Гашение: РЕГ '037' (cpu.c:559-563), разряд 18 гасится (не в
  GRP_WIRED_BITS, cpu.c:71-76).
- Диспетчеризация 0500 → обвнп1+30 = 04023 — выполняет ГОСТЕВОЙ disp70;
  эмулятор только определяет адрес ячейки (defs.h:401-404).
- выпр (cpu.c:1676-1697): PC = M[(reg&3)|030]; op_int_1 сохраняет
  возврат в M[IRET=033] — сходится.
- ЛОВУШКА: стоковый ДИСПАК 01457 (ПОДПРГ) / 01460 (ГАШРП1) не пропускают
  18Р — тесты обязаны патчить (run-gp-irq.py:218-224: d 01457
  0000000036774000, d 01460 7777777701003000).

## 4. ЭК 50 в пользовательском режиме

- э50 → PC = 0550, супервизор, M[14] = Aex (cpu.c:1511-1561, 1555-1556);
  трассировка TRACE GP-EK050 при 01200<=Aex<=01237 (cpu.c:1521-1526).
- Перехвата 01210-01217 до векторного входа НЕТ; BESM6_NITI_USER не
  читается ни одним C-файлом (только BESM6_NITI_DEBUG и
  BESM6_DUBNA_PLOT_KEEP в gp_decoder.c). Тесты выставляют
  BESM6_NITI_USER=1 — переменная НИЧЕГО не делает; doc/BENSON-501.md:125-129
  не соответствует коду.
- ЭК 50 из задачи → 0550 → гостевое ВЗУ Э1 → (по ЭК-ТРАССИРОВКА.md:42-56)
  ЭКЛИСТ → ТВ40 → БОЭК1 → ВИСП → нерезидент.

## 5. Тайминги/принтер

- SLOW_START = 100*MSEC, FAST_START = 1*MSEC (printer.c:62-63); после
  стопа мотора первый старт 100 мс модельного времени; события барабана
  планируются по host-часам (sim_activate 1.4 мс/символ), таймер 250 Гц
  калибруется так же (cpu.c:2079-2117).
- THROTTLE есть в scp.c:2815-2816 (THROTTLE/NOTHROTTLE → sim_set_throt),
  базовый OSZAGR/dispak.ini:6 содержит set throttle=1m. (В наших прогонах
  эта строка дала «Non-existent device: THROTTLE» — проверить синтаксис
  `set throttle=1m` vs `set throttle 1m` и контекст команды.)
- «СБОЙ АЦПУ0» на полной скорости: без throttle CPU исполняет на порядки
  больше команд между синхроимпульсами барабана, гостевой тайм-аут
  ожидания высыхает в машинном времени → сбой. set throttle=1m
  восстанавливает согласование (вывод из устройства таймингов; отдельного
  документа о НОМВ нет).

## 6. Тесты (как подают колоду)

run-gp-star.py: tmux; ДATA: → ДАЙ А0/А1, НОМВ → C-g; до 3 попыток:
reset АЦПУ (detach/attach -n prn0/prn1), at vu0 <deck>, d 6 1, d 5 10,
set cpu req, go; конец — свой маркер АЦПУ; GPSTAR_CPU_DEBUG=1 добавляет
set cpu debug + set console log=cpu.log. Диски: md00=2053, md07=2253,
md41=2148, md45=NITI 2348.
run-gp-irq.py: load gp-irq-handler.b6 на 077700, патч мл. 15 бит ячейки
04023, патч 01457/01460, set gp tv67, set gp testirq, go; успех =
«18Р line raised» → «TRACE GRP18 -> op_int_1 0500» → «TRACE РЕГ 037 GRP
clear» → «TRACE ВЫПР interrupt return».
run-gp-fig.py: грузит 14 кадров в память, вектор 04023 → 077710,
обработчик стримит кадры ПОСЛОВНО через увв 172 (gp_data_write →
benson_frame). ЭК 01211 не используется из-за маски 04377 (явно отмечено
в run-gp-fig.py:17-18).

## 7. ИТОГ: гостевой ДУДКА vs simh

| Нужна гостю | Есть в simh | Что сломается |
|---|---|---|
| РЕГ '34' (инициализация) | cmd_002 034 → gp_config_write | работает, безвредно (МПРП пишет только УВВ 034) |
| РЕГ '240' (чтение слова на 18Р) | cmd_002 0240 → gp_data_read | возвращает gp_buf, который наполняет только сам гость |
| УВВ '4023' (опрос состояния) | НЕТ — STOP_UNIMPLEMENTED | СИМУЛЯТОР ОСТАНАВЛИВАЕТСЯ — критический пробел |
| УВВ '155' (вкл/выкл) | pi_control (перфоратор) | семантики ГП нет |
| УВВ '164'/'165' (байты) | pi_write (перфоратор) | данные в ГП не попадают |
| УВВ '166' (состояние) | pi_read (мусор) | нет статуса ГП |
| УВВ '4102' (готовность 13/9) | ACC=READY2 (PI2_START) | разряд не ГП |
| 18Р + 0500 + 04023 + РЕГ 037 | есть | работает; НО 01457/01460 стока не пропускают 18Р (нужен патч) |
| ФИЗОБМ-чтения зон МБ | drum/disk_io | работает |
| ЭК-хуки 01210-01217 | мёртвый код (маска 04377) | гостевому пути не нужны |
| BESM6_NITI_USER | не читается | мёртвая переменная |

Реальный интерфейс БЕНСОНа в ДИСПАКе висит на регистрах перфоратора
ПИ-1 (0155/0164-0166/4102, ПРП 19 — doc/ГП.md §8:392-455); в simh всё
это обслуживает перфоратор. Рабочий контур сегодняшнего GP —
синтетический: УВВ 0172/0173 + 18Р + вектор 04023.
