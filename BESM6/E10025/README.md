# Электроника-100-25 (подсистема ЕМВС М5 «Вьюга»)

Опытная simh-модель периферийной вычислительной системы, созданная на базе
эмулятора PDP-11 (`simh/PDP11`). Источники: книги 3 и 4 ИЧМ2.791.003
(1977 г.) из каталога Documentation/электроника 100-25; фактические находки и
номера страниц записаны в `../../.localdocs/E10025-BOOK3-ISA.md`,
`E10025-BOOK4-CHANNEL.md` и `E10025-VS-PDP11.md`.

## Что есть
- `e10025_cpu.c`: 16-битный CPU, 8 методов адресации, команды книги 3,
  PSW N/Z/V/C/T/IPL, прерывания через векторную таблицу.
- `e10025_io.c`, `e10025_io_lib.c`, `e10025_defs.h`: переиспользованный
  шинный слой simh PDP-11 (DIB, iopage, calc_ints/get_vector, DMA map).
- `e10025_chan.c`: модель единого канала по книге 4: фазы СА/СП, 18-битный
  адрес, DMA НДК (РСУ/РД/РАП/РСС), BR7..BR4 арбитраж, счётчики циклов/ошибок.
- `e10025_cpumod.c`: регистры CPU по адресам канала 777700..777707,
  777774 (граница стека), 777776 (РСП), MTAB режимов, файла калибровки и
  размера ОЗУ; именованные регистры рис. 11 с пометкой `[GAP]`.
  Модификатор `BOOTEVENTS` добавляется в `e10025_cpu.c` в копию MTAB при reset.
- `e10025_cal.c`: три режима скорости (`ticks`, `historical`, `fast`), таблица
  поправок 1998 года по opcode, длительности книги 3 по классам и методам
  адресации, счётчик `CPU TICKS`, планирование задержек на часах SIMH,
  загрузка текстового файла при reset/startup и debug-строки калибровки.
- `e10025_fp.c`: FADD/FSUB/FMUL/FDIV по книге 3, стек через R, одинарная
  точность; арифметика переиспользована из simh PDP-11 (`pdp11_fp.c`).
- `e10025_stddev.c`, `e10025_sys.c`: консоль, часы, таблица устройств.
- `e10025_rk.c`, `e10025_rl.c`: переиспользованные под MIT контроллеры simh
  PDP-11 RK11/RK05 и RL11/RL02. RK зарегистрирован по CSR `01777400`,
  вектор `0220`, RL по CSR `01774400`, вектор `0160`. DP остаётся `[GAP]`:
  в этом дереве simh нет `pdp11_dp.c`, и выдумывать его поведение нельзя.
- `e10025_cr.c`, `e10025_pt.c`, `e10025_lp.c`: карточитатель CR11/CD11,
  reader и punch перфоленты PC11 и принтер LP11, переиспользованные под MIT
  из simh PDP-11. CR по CSR `017160`, вектор `0230`; PTR/PTP по CSR
  `017550`/`017554`, но векторы перенесены на `0264`/`0270`, потому что
  `0070`/`0074` в этой модели занимает DMA НДК; LPT по CSR `017514`,
  вектор `0200`. `017550` также более не дублируется в таблице регистров
  диспетчера памяти.

- `e10025_rh.c`, `e10025_rp.c`: контроллер RH11 и диск RP04/05 как прототип
  20-Мбайт DP-диска из статьи 1998 года. `RHA` по CSR `0176700`, вектор
  `0254`, BR5. Тождество RP04/05 историческому DP не доказано `[Г]`: register map
  DP в доступных источниках отсутствует.

### Карточные устройства и перфолента

Книги 1 и 2 1981 года не упоминают читатель перфокарт, поэтому CR11 это
прототип PDP-11, а не документально подтверждённое устройство 100-25.
Перфолента и принтер подтверждены книгами: FS-1501, ПЛ-150М и DZM-180
имеют те же адреса `017550/017554/017514`, что и контроллеры simh.
Вектор DZM-180 в книге не приведён, поэтому `0200` взят из simh.

## Диски RK05 и RL02 (Phase F)

Контроллеры перенесены из проверенных `PDP11/pdp11_rk.c` и
`PDP11/pdp11_rl.c` с сохранением MIT-уведомления. Адаптация ограничена
заголовком `e10025_defs.h`, 16-разрядным DMA `Map_ReadW`/`Map_WriteW`,
Boot ROM через `WrMemW` и вызовом `cpu_set_boot`, который определён в
`e10025_sys.c` по образцу `pdp11_cpu.c:3555`: `saved_PC = pc`, `PSW = 0340`.
E10025 дополнительно пишет `R[7]`, потому что `sim_instr` берёт PC оттуда.

```
set RK enabled
attach RK0 /tmp/.private/azizz/opencode/emvs/phasef/rtv4_rk_boot.dsk
show RK0
set RL enabled
set RL1 RL02
attach RL1 /tmp/.private/azizz/opencode/emvs/phasef/rtv53_rl_work.dsk
show RL1
```

публикации: RK05 simh даёт 1672704 байта, что совпадает с каноническим
образом; к DP применять нечего.

### Модификатор загрузочных событий CPU

```
set CPU BOOTEVENTS=off|on
show CPU BOOTEVENTS
```

По умолчанию выключен: все прежние детерминированные тесты сохраняют
 логический цикл `sim_interval = 1000` без вызова `sim_process_event`.
Оба раннера RT-11 включают `set CPU BOOTEVENTS=on`; в этом режиме
`sim_instr` убывляет `sim_interval` и вызывает `sim_process_event`, когда
счётчик доходит до нуля, поэтому отложенные события RK/RL доходят до гостя
даже при плотном опросе регистров. Опрос регистра канала не отменяет уже
поставленное событие диска.

Семантика CPU, уточнённая по трассе гостя Phase F3 и эталонному PDP-11:

- `mem_index()` больше не маскирует адрес на `(MEMSIZE>>1)-1`: это
  нестепень двойки, маска сбрасывала бит 10 и совмещала стек гостя
  `0007774` со словом `001776`, куда писал DMA RK. Адрес сектора теперь
  продвигается `02 -> 06 -> 010 -> 012 -> 020`, как в эталоне.
- Байтовые одноадресные команды `105xxx` (`CLRB ... TSTB`) теперь идут
  в общий декодер вместо старшей группы ветвлений: `TSTB (R1)` в
  загрузчике больше не вызывает `TRAP_ILL`.
- Код `011` нулевого opcode это `BNE`, а не `SOB`; `SOB` остаётся в
  группе `07`. Ложный переход в обработчик ошибок устранён.
- `CFCC` (`0170000`) копирует флаги FPS в PSW по образцу `pdp11_fp.c:311`,
  а не вызывает `TRAP_ILL`.

Гостевая RT-11 V4.00C теперь загружается до приглашения `.`. Корень расхождения
состоял в потере `TRAP_NXM` при обращении к незанятому адресу страницы ввода
вывода: загрузчик проверяет верх ОЗУ командой `MOV (R4),(R4)` по `001064` и
ожидает ловушку с вектором `000004`, заранее поставленным в `001070`. В эталоне
запись по `0160000` вызывает `ABORT (TRAP_NXM)` (`PDP11/pdp11_cpu.c:2824-2838`),
а E10025 молча возвращал нулевое слово и продолжал цикл до `0170000`. Отсюда
смещение релокации отличалось на `010000`, и вектор EMT `000030` указывал
на `HALT`. Теперь все четыре пути `ReadW`, `ReadB`, `WriteW`, `WriteB`
проверяют наличие dispatch записи или чтения и поднимают `TRAP_NXM` для
незарегистрированных адресов страницы ввода вывода. Вторая ошибка, найденная
трассой уже после загрузки монитора, была в `MOVB` в регистр: старший байт
сохранялся вместо знакового расширения, из-за чего `TYPE V4USER.TXT` после
`.TYPE` приводил к `HALT`. Обе исправлены минимальным патчем в `e10025_cpu.c`.
Тесты `tests/run_rt11_boot.sh` и `tests/run_rt11_c.sh` дают PASS. Раннеры
используют псевдотерминал `script(1)`, потому что SIMH не читает клавиатуру
из обычного канала. Контроллеры на уровне устройств проверены: `attach`,
`show`, адрес и вектор совпадают с ожидаемыми; все 11 прежних PASS-строк
по модулям сохранены. DP и перечисленные выше `[GAP]` остаются в силе.

## Калибровка по командам и режимы скорости

Три режима выбираются командой `set cpu mode=...`. По умолчанию включён
`ticks`, поэтому все существующие тесты продолжают работать без изменений.

```
set cpu calfile=/tmp/e10025.cal        # только для режима ticks
set cpu mode=ticks|historical|fast
set cpu memdisp=on|off                 # необязательная добавка 0.15 мкс/цикл
set debug /tmp/e10025-debug.log
set cpu debug=CALIB
go
examine CPU TICKS
show cpu mode
show cpu memdisp
```

- `ticks` (по умолчанию): файл поправок 1998 года по opcode. Для каждого opcode
  из таблицы поправка добавляется к `CPU TICKS`, а при включённом CPU debug в
  лог пишется строка `calib: op 012700 delta 3`. Это прежняя модель калибровки,
  сохранённая без изменений.
- `historical`: длительности из книги 3 (печ. с. 109-112, таблицы 5-11) в
  микросекундах. Каждая длительность планируется на часах SIMH через
  `sim_timer_activate_after` из `sim_timer.h` и списывает документированное
  модельное время. `CPU TICKS` считает применённые единицы задержки, а debug
  даёт строку `hist: op 012700 MOV 1.60us 0cy 8inst active 1`. Здесь не
  используется неизвестный файл разности 1998 года.
- `fast`: ни поправок, ни задержек, `CPU TICKS` равно 0.

Файл по умолчанию `e10025.cal` загружается при reset/startup, если он есть.
Команда `set cpu calfile=<path>` загружает другой файл сразу и повторно при
последующих reset. `show cpu mode` и `show cpu calfile` показывают состояние.
Формат файла прежний: одна строка `opcode delta`, opcode восьмеричный, delta
восьмеричный с ведущим `0` или десятичный, комментарии с `#` или `;`.

### Длительности книги 3 (режим historical)

Формула книги 3 (печ. с. 109): `t = t_src + t_dst + t_exec`. Для MOV берётся
`t_src + t_exec`, для одноадресных команд `t_dst + t_exec`, для ветвлений,
управления программой и MFPI/MTPI только `t_exec`.

- Таблицы 5 и 6, методы 0..7: `t_src`/`t_dst` = 0.00, 0.94, 1.00, 1.88, 1.00,
  1.88, 1.60, 2.30 мкс; циклы 0, 1, 1, 2, 1, 2, 2, 3. Для ADD, SUB, CMP, BIT,
  BIC и BIS при нулевом методе источника и приёмнике 1..7 берутся скобочные
  значения таблицы 6: 1.10, 1.10, 1.98, 1.10, 1.98, 1.90, 2.70 мкс.
- Нечётный байт добавляет 0.42 мкс в таблицах 5, 6 и 9; для MOV по таблице 8
  используется отдельный столбец нечётного байта, где добавка равна 0.54 мкс.
- Таблица 7: ADD/CMP/BIT/BIC/BIS 1.2 / 1.78 / 2.18 мкс, SUB 1.2 / 1.78 / 2.36,
  XOR 1.2 / нет значения / 2.18. Число 4.78 в скобках у значения 2.18 не
  объяснено в книге, поэтому оно не применяется.
- Таблица 8 (MOV) по методам приёмника и источника: 1.0..4.36 мкс, включая
  нечётный байт 2.02..4.66 мкс; циклы 0..4.
- Таблица 9 (одноадресные): 1.2 / 2.36 мкс для CLR, COM, NEG, INC, DEC, ADC,
  SBC, TST, ROL, ASL, SWAB; 1.4 / 2.54 для ROR и ASR; 1.0 / 2.18 для SXT.
  Циклы 1 / 2.
- Таблицы 10 и 11: MFPI 4.3 мкс, MTPI 4.2 мкс (по 2 цикла); ветвления 2.1 мкс
  при переходе и 1.7 без перехода; SOB 2.8 / 2.5 мкс.
- По печ. с. 109 при использовании диспетчера памяти время растёт на 0.15 мкс
  за каждый цикл памяти. Режим включается отдельно `set cpu memdisp=on` и по
  умолчанию выключен; это единственное упоминание диспетчера памяти на этих
  страницах.

`[GAP]`: в таблицах 5-11 нет времён для MUL, DIV, ASH и ASHC, неизвестно
значение 4.78 у ADD и других команд таблицы 7, в таблице 8 первые две строки
имеют 0 циклов при ненулевом времени. Эти классы получают нулевую поправку и не
падают; честность важнее выдуманного числа. Строка про 0.18 мкс для RORB и ASRB
на печ. с. 112 частично перекрыта рукописью и тоже не применяется.

Честная граница: 75 нс и 150 нс меньше одного тика SIMH, `sim_timer` округляет
такие интервалы до одной инструкции, поэтому режим `ticks` применяет поправки
как тики симулятора. `sim_clock_coschedule` (`sim_timer.c:3409-3416`) считает
интервал в единицах симулятора и делит его на размер тика, поэтому 1-4 мкс при
калиброванном CLK обращаются в 0 тиков. Для микросекунд используется родственная
функция `sim_timer_activate_after` (`sim_timer.c:3171-3215`), которая принимает
микросекунды напрямую. Перевод в единицы симулятора идёт по калиброванной
скорости `sim_timer_inst_per_sec`, поэтому точность времени host не заявляется:
проверяется факт планирования события и рост счётчика, а не жёсткое равенство
настенных часов. Числа 150/75/75/75, 450, 525 и 15000 это исторические
значения книги 4, а не измеренное время host.

## Режим тайминга канала

По умолчанию включён логический режим. Он сохраняет детерминированный журнал
фаз Phase 3 и прежний цикл `sim_instr` без вызова `sim_process_event`.

```
set CHAN TIMING=logical
set CHAN TIMING=scaled
set CHAN NOSP=0
set CHAN NOSP=1
show CHAN TIMING
show CHAN NOSP
```

В масштабированном режиме `scaled` переходы фаз планируются через
`sim_activate`, а таймаут 15 мкс отдельно через `sim_activate_after` и
отменяется через `sim_cancel` при приходе К СП Н. Объявленный масштаб: один
тик симулятора равен 75 нс, установка 150 нс равна двум тикам, каждая
последующая фаза 75 нс равна одному тику, полный цикл 525 нс равен семи
тикам. Повтор цикла 450 нс и таймаут 15000 мкс остаются историческими
величинами книги 4. Это объявленный масштаб модели, а не реальные
наносекунды host. `sim_activate_after` переводит микросекунды в инструкции
по скорости симулятора, а не по времени хоста.

Данные по-прежнему возвращаются синхронно: контракт `ReadW`/`WriteW` и путь
DMA не изменились. Счётчик `TIMEOUT` растёт только при искусственном
подавлении СП (`NOSP=1`), при успешном обмене он не меняется. В режиме
`scaled` цикл `sim_instr` убывляет `sim_interval` и вызывает
`sim_process_event` по образцу PDP-11. Логический режим оставляет прежнюю
обработку интервала без вызова обработчика событий в цикле.

| Перфолента вывод, состояние и данные | `777554`, `777556` |
| Клавиатура, состояние и данные | `777560`, `777562` |
| Печать, состояние и данные | `777564`, `777566` |
| Мозаичный принтер, состояние и данные | `777514`, `777516` |
| Интерфейс гибкого диска, команды и данные | `777170`, `777172` |

Текущая модель уже использует документированные адреса для PTR, PTP, TTI,
TTO и LPT. Гибкий диск `777170/777172` не реализован. GAP-таблица диспетчера
памяти содержит пока по одному показательному адресу из каждой группы;
полный набор из Книги 2 можно добавить как pass-through, не выдумывая битовые
форматы. Источник: `.localdocs/OZU248-BOOK2-RECONCILE.md`, раздел 6.

## Размер ОЗУ и карта адресов по книге 4

Документ `ОЗУ 248К - Книга №1.pdf` из архива `RAM-248K-01.rar` даёт ёмкость
платы 248 Кбайт, то есть 124K 16-разрядных слов при `К = 1024`. Это совпадает
с максимумом 124K слов в книге 4. Время выборки не более 650 нс, цикл чтения
не более 800 нс, записи не более 1100 нс, период регенерации 15 мкс с
допуском плюс-минус 0,5 мкс, время регенерации не более 600 нс. Документ также
упоминает исправление одиночной и обнаружение двойной ошибки при чтении, но
не даёт формат синдрома и регистры ошибок, поэтому ECC в модели не создаётся.

Вариант по умолчанию приведён к документированным 124K слов (248 Кбайт).
Значение 125K слов сохраняется как compatibility option и в документации
не значится; сверка зафиксирована в `../../.localdocs/OZU248-RESEARCH.md`.
Команда
`set CPU MEMSIZE=64K` включает прежний режим совместимости на 64 Кбайт
(32K слов); доступен также `MEMSIZE=124K`. `show CPU` и `show CPU MEMSIZE`
печатают `MEMSIZE=124K words` по умолчанию.

```
set CPU MEMSIZE=64K
set CPU MEMSIZE=124K
set CPU MEMSIZE=125K
show CPU
show CPU MEMSIZE
```

Книга 4 (печ. с. 38) указывает 18-разрядный адрес канала: 128K ячеек полными
словами, область ОЗУ `0..0757777`, максимальная ёмкость 124K слов, область
устройств `0760000..0777777`. По умолчанию выделяется не менее 128K слов,
разряды АДР17..АДР16 адреса канала выбирают банк ОЗУ без выхода за границы
массива. Последнее слово конфигурации 124K слов имеет адрес `0757776`
(253950 десятичных) и доступно через консоль. Все зарегистрированные адреса
устройств лежат выше 256000, поэтому страница ввода/вывода и окно гостевых
регистров `0160000..0177777` не изменились. Проверка в `tests/test_memory.sh`.

## Регистры рис. 11 с неизвестным форматом

Закрытие Phase P7: все поименованные регистры рис. 11 (печ. с. 39) по точным
адресам книги реализованы как pass-through хранилище одного слова:

- `777656`, `777640`, `777616`, `777600`: диспетчер памяти пользователя,
  подписи ГРАС и БРИС;
- `777576`, `777572`: состояние диспетчера памяти;
- `777570`: пульт управления;
- `772356`, `772340`, `772316`, `772300`: диспетчер памяти внутреннего
  режима, подписи БРАС и БРИС.

Адрес `777550` в этой таблице не дублируется: он отдан контроллеру PTR.
Регистр `777546` (таймер) занят CLK, а `777566` входит в блок TTO
`017564..017567`, поэтому новые DIB для них не создаются. Прежняя запись
`777236..777200` в старом аудите помечена `[УСТ]` и не используется: сверка
рис. 11 подтвердила адреса `772356..772300`.

Форматы разрядов перечисленных регистров в книге отсутствуют, поэтому они
остаются `[GAP]`. Модель хранит записанное слово и возвращает его при чтении;
никакие флаги, прерывания, режимы трансляции или другая семантика не
выдумываются, начальное значение `0`. PDP-11-подобный MMU не создаётся:
18-разрядный адрес канала, банки ОЗУ и окно гостевых регистров
`0160000-0177777` работают как прежде. Проверка всех адресов, pass-through
записи и отсутствия побочных эффектов выполнена в
`tests/test_register_map.sh` (T5-T7).

## Ограничения
- Наносекундные задержки канала (150/75/75/75 нс, повтор 450 нс, полный цикл
  525 нс, таймаут 15 мкс) это исторические значения книги 4. Логический режим
  сводит их к состояниям и счётчикам, режим `TIMING=scaled` использует
  объявленный масштаб один тик = 75 нс, но не реальное время хоста.
- Дайзи-чейн внутри уровня BR моделируется как упорядоченный диагностический
  список источников (`set CHAN BRDEV`): запросивший источник перехватывает ПК,
  первый от процессора имеет высший полууровень. Исторический порядок
  подключения реальных устройств к линиям ПК4...ПК7 в книге не приведён,
  поэтому топология списка остаётся `[GAP]`.
- PDP-11-подобный MMU/CMS и «диспетчер памяти» как аппаратный блок не
  смоделированы. Книга 3 (печ. с. 109, примечание 3 к таблице 5) только
  упоминает диспетчер памяти как причину дополнительных 0,15 мкс на цикл,
  а книга 4 (печ. с. 17, рис. 2; печ. с. 38, разд. 8) задаёт 18-разрядный
  адрес канала с двумя разрядами расширения и ОЗУ до 124K слов. Регистров
  трансляции, страниц и защиты в книгах нет. Сами 18-битные адреса, расширение
  адреса, банки ОЗУ 124K слов по умолчанию и окно регистров
  `0160000-0177777` реализованы, что проверено в `tests/test_register_map.sh`
  и `tests/test_memory.sh`; DMA доступен через `set DMA ...`. Форматы регистров
  диспетчера памяти остаются `[GAP]`.
- Подключение к БЭСМ-6/ЕМВС М5: реализован КАДОПАМ DKSE bridge по образцу
  `PDP11/pdp11_dks.c`, тест БЭСМ-6-совместимых кадров PASS (базовый лог
  `../../.localdocs/E10025-DISCREPANCY-BASELINE.txt`). Интеграция в simh BESM6
  идёт через готовый REMOTE-клиент, отдельный канал КРК не создавался. Канал 2
  используется для первого теста, позже возможны каналы 1 или 3.
- VT52 и 15-ИЭ-013 не моделируются: это интерфейс программы-эмулятора на ПК,
  а не архитектура 100-25; на машине есть отдельный эмулятор терминала 15ИЭ
  в `/home/azizz/Yandex.Disk/ie15/`.

### Плата ISA-UNIBUS: hardware-only граница

По публикации 1998 года (с. 21-22) плата ISA-UNIBUS это внешнее аппаратное
устройство: ПЛИС Altera 7032 (15 нс), КР559ИП1 и КР559ИП2, выходы 25 мА,
напряжение +5 В. По блок-схеме на плате: регистры 0300v2, 0704B, 1108B,
1512B и контроллер INTR v2, поля адреса 0-3, 4-7, 8-11, 12-15, буферы
данных D0-D15, A16-A17 от Vcc. Это не программно видимая часть
Электроника-100-25, виртуальные регистры по умолчанию не добавляются.
Виртуальные регистры добавляются только при документально подтверждённой
потребности гостевой программы.

## Граница совместимости

Архитектурно совместимо с PDP-11/40 и единым каналом Электроника-100-25 на
уровне системы команд, PSW, векторов прерываний, 18-битного адреса, банков
ОЗУ 124K слов по умолчанию и порядка фаз обмена; реальные исторические наносекунды,
плата ISA-UNIBUS, DP, VT52 и PDP-11-подобный MMU не смоделированы. RK05 и RL02
подключены как устройства simh, и загрузка гостевой RT-11 V4.00C в E10025
теперь завершается успешно; найденные ошибки CPU и граница исправления
записаны в `../../.localdocs/E10025-GAP-F2-EVIDENCE.txt` и
`../../.localdocs/E10025-GAP-F5-EVIDENCE.txt`. DP остаётся `[GAP]`.
Дайзи-чейн внутри уровня BR представлен диагностическим списком источников
без исторической топологии устройств. Пооперационная калибровка 1998 года
реализована как тики симулятора; режим `historical` добавляет документированные
микросекунды книги 3 через часы SIMH, но не заявляет точности настенных часов
хоста и не восполняет `[GAP]` классы MUL, DIV, ASH и ASHC.
Масштабированный режим канала использует объявленный коэффициент, а не
реальные наносекунды хоста. Это архитектурная совместимость с оговорками, а не
заявление о полной исторической точности по публикации 1998 года.
