# Электроника-100-25: руководство пользователя

Краткое руководство по запуску машины Электроника-100-25 (периферийная вычислительная система М5 «Вьюга») и подключению терминала 15-ИЭ-013. Модель построена на основе программы simh PDP-11, подробности приведены в файле `README.md`. Адреса и вектора записаны в восьмеричной системе. Все команды взяты из исходного кода и проверочных сценариев проекта.

## 1. Сборка
Из каталога `BESM6/E10025` выполните команду:
```
make -f Makefile BIN=/tmp/e10025
```
Параметр `BIN` задаёт полный путь к готовой программе, параметр `BUILD` задаёт каталог промежуточных файлов (по умолчанию `build`). Оба каталога находятся на этом компьютере и не добавляются в историю версий git. Проверочные сценарии получают программу через переменную окружения:
```
E10025=/tmp/e10025
```
Если переменная `E10025` не задана, сценарии ищут файл `build/e10025` рядом с собой.

## 2. Минимальный запуск
```
/tmp/e10025
sim> show devices
```
Команда `show devices` печатает устройства рабочего состава. В исходниках их шестнадцать, а не семнадцать: такой список задан в файле `e10025_sys.c` и проверен сценарием `tests/test_devices.sh`.

| Имя | Что это |
|---|---|
| `CPU` | шестнадцатиразрядный процессор, восемь способов адресации, флаги и прерывания |
| `SYSTEM` | системные регистры и доступ к размеру оперативной памяти |
| `CLK` | часы модели |
| `TTI` | ввод с пункта управления, клавиатура |
| `TTO` | вывод на пункт управления |
| `CHAN` | единый канал, фазы обмена и арбитраж запросов уровней от BR7 до BR4 |
| `DMA` | доступ канала к памяти через карту прямого доступа |
| `DKSE` | мост КАДОПАМ к машине БЭСМ-6 |
| `RK` | контроллер RK11 и диск RK05 |
| `RL` | контроллер RL11 и диск RL02 |
| `CR` | читатель перфокарт CR11/CD11 |
| `PTR` | читатель перфоленты |
| `PTP` | перфоратор перфоленты |
| `LPT` | принтер |
| `RHA` | контроллер RH11, временный вариант контроллера диска DP |
| `RP` | диск RP04/05 в составе пары RHA/RP |
Терминалов VT52 и 15-ИЭ-013 в этом списке нет, они работают отдельными программами. Выход из программы: `quit`.

## 3. Загрузка операционной системы RT-11 версии 4
Образ диска, принятый за исходный: `/tmp/.private/azizz/opencode/emvs/rt11/kits/Disks/rtv4_rk.dsk`, размер 1672704 байта. Отпечаток файла по алгоритму SHA256:
```
ebf0da98feffe3cd82aad95c3f4143757be512199058f996fc15e7e96c173978
```
Проверочный сценарий сверяет отпечаток до команды `attach`. Рабочую копию кладут в отдельный каталог:
```
mkdir -p /tmp/.private/azizz/opencode/emvs/phasef
cp /tmp/.private/azizz/opencode/emvs/rt11/kits/Disks/rtv4_rk.dsk \
   /tmp/.private/azizz/opencode/emvs/phasef/rtv4_rk_boot.dsk
```
Минимальный файл настроек `.ini` (копия должна лежать в рабочем каталоге):
```
set CPU BOOTEVENTS=on
set RK enabled
attach RK0 rtv4_rk_boot.dsk
boot RK0
```
В диалоговом режиме достаточно команд `set RK enabled`, `attach RK0 rtv4_rk_boot.dsk` и `boot RK0`. Без `set CPU BOOTEVENTS=on` при частом опросе устройства RK отложенные события диска не доходят до операционной системы внутри модели. Команда `set RK0 AUTOBOOT` недоступна, это `[GAP]`.
Ожидаемые строки на пункте управления:
```
RT-11SJ  V04.00C
Welcome to RT-11 Version 4
.
```
После приглашения `.` можно набрать `DIR` и получить список файлов. Для ввода с клавиатуры нужна настоящая терминальная линия: SIMH не читает клавиатуру из обычного потока ввода, поэтому проверочный сценарий запускает программу через команду `script`.
```
E10025=/tmp/e10025 bash tests/run_rt11_boot.sh
```
Успех это строки `PASS[hash]`, `PASS[rk]` и последняя строка `PASS: RT-11 V4.00C booted from canonical RK05 and DIR listed files`. Журнал работы: `/tmp/.private/azizz/opencode/emvs/phasef/rt11_v4_boot.log`.

## 4. Программа DECUS C
Диск с программой DECUS C, принятый за исходный: `/tmp/.private/azizz/opencode/emvs/rt11/extracted/RT-11 V2.0 Freeware CD/dsk/misc/decusc.dsk`, размер 228352 байта. Отпечаток файла по алгоритму SHA256:
```
f00977cd292222bcc59326a5677d9320a434976ae2cf5ea1039d385e6ea94e51
```
Проверочный сценарий сверяет отпечатки обоих образов, делает копии, подключает их как `RK0` и `RK1`, заранее записывает файл `HELLO.C` в копию диска (пункт управления RT-11 переводит ввод в верхний регистр) и выполняет команды:
```
ASSIGN RK1: C:
RUN C:CC C:HELLO.C
RUN C:AS HELLO.S/D
LINK/BOT:2000 HELLO.OBJ,C:SUPORT,C:CLIB
DIR HELLO.*
RUN HELLO
```
Ключ `/BOT:2000` обязателен по руководству DECUS C, иначе функция `printf()` может выдать сообщение `M-trap to 4`. Ожидаемая строка: `Hello, RT-11!`.
```
E10025=/tmp/e10025 bash tests/run_rt11_c.sh
```
Успех это строка `PASS: DECUS C chain printed Hello, RT-11!`. Журнал работы: `/tmp/.private/azizz/opencode/emvs/phasef/rt11_c_run.log`.

## 5. Подключение терминала 15-ИЭ-013
Терминал работает отдельной программой из каталога `/home/azizz/Yandex.Disk/ie15/`. Внутри E10025 нет ни VT52, ни 15-ИЭ-013, нет постоянного запоминающего устройства `chargen-15ie.bin`, кадра 80 на 25 знаков, виртуального курсора и команды `set TTO IE15`. Устройства ввода `TTI` и вывода `TTO` связаны с линией `telnet` программы SIMH через функцию `tmxr_set_console_units`, поэтому терминал подключается к уже существующему пути ввода и вывода, а не к новому устройству.
В работающей модели задайте номер порта вне диапазона 4204..4210, например 4301:
```
sim> set console telnet=4301
```
На стороне терминала выполните команду, описанную в файле `ie15/README.md`:
```
cd /home/azizz/Yandex.Disk/ie15
python3 -m ie15emu --line tcp://127.0.0.1:4301 --dump - --status
```
Параметр `--dump` включает работу без графического окна. Чтобы вывод работающей программы доходил до терминала, дополнительно включите `set CPU BOOTEVENTS=on`. Проверка использует свободные порты из диапазона 43100..43399.
Первое соединение принимается первой же командой `step`, после чего линия выдаёт приветствие программы SIMH, а не текст рабочей программы:
```
Connected to the ELECTRONICA-100-25 simulator CON-TELNET device
```
Проверочный сценарий `tests/test_ie15_guest_echo.sh` выводит через устройство `TTO` строку `P6GUEST7` (её можно изменить переменной `GUEST_TEXT`). Эту строку должен увидеть терминал.
```
E10025=/tmp/e10025 bash tests/run_ie15_link.sh
E10025=/tmp/e10025 bash tests/test_ie15_guest_echo.sh
```
Исходный код и постоянное запоминающее устройство ie15 не копируются в E10025, файлы ie15 не изменяются. Используется готовый способ соединения `tcp://`, `ssh://` или `stdio://`.

## 6. Полезные режимы
Размер оперативной памяти, по умолчанию 124K слов (248 Кбайт), вариант 125K оставлен для совместимости:
```
set CPU MEMSIZE=64K
set CPU MEMSIZE=124K
set CPU MEMSIZE=125K
show CPU MEMSIZE
```
Скорость: режим `ticks` по умолчанию с поправками 1998 года для каждого кода команды, режим `historical` задаёт длительности по книге 3 через часы SIMH, режим `fast` работает без поправок и задержек:
```
set CPU MODE=ticks
set CPU MODE=historical
set CPU MODE=fast
set CPU CALFILE=/tmp/e10025.cal
set CPU MEMDISP=on
show CPU MODE
```
Режим отсчёта времени канала, по умолчанию `logical`, в режиме `scaled` один шаг модели равен 75 наносекунд:
```
set CHAN TIMING=logical
set CHAN TIMING=scaled
show CHAN TIMING
```
Проверка канала: `BRDEV` добавляет источники в последовательную цепочку запросов BR, все поля восьмеричные, уровень от 4 до 7, номер позиции от 0 до 7. Параметр `NOSP` подавляет сигнал ответа, чтобы проверить превышение времени ожидания.
```
set CHAN BRDEV=4:0:0114
set CHAN NOSP=0
set CHAN NOSP=1
set CHAN DEBUG
show CHAN BRDEV
show CHAN NOSP
```
Отладка и настройка времени:
```
set debug /tmp/e10025-debug.log
set CPU DEBUG=CALIB
go
examine CPU TICKS
```
Параметр `DEBUG=SIG` для канала пока не работает, это `[GAP]`.

## 8. Честные ограничения
- Наносекундные задержки канала (150/75/75/75 наносекунд, повтор 450, полный цикл 525, ожидание 15 микросекунд) это исторические значения книги 4. Режим `logical` сводит их к состояниям и счётчикам, режим `scaled` использует объявленный масштаб, но не реальное время компьютера.
- Подобный PDP-11 блок управления памятью и «распределитель памяти» не реализованы. Форматы регистров `777600..777656`, `772300..772356` и `777572/574/576` остаются неизвестными, это `[GAP]`. Реализованы восемнадцатиразрядный адрес канала, банки оперативной памяти до 124K слов и окно регистров `0160000-0177777`.
- Плата ISA-UNIBUS это внешнее аппаратное устройство (программируемая логическая схема Altera 7032, микросхемы КР559ИП1 и КР559ИП2, напряжение плюс 5 вольт). Она не видна программам машины. Виртуальные регистры добавляют только если они нужны программе, работающей в модели.
- Диск DP остаётся временным вариантом `[Г]`: контроллер RH11 работает с шиной MASSBUS, а DP в RT-11 это RP11/RP02/03 на шине UNIBUS. Файла `pdp11_dp.c` в дереве исходников нет, карты регистров DP для машины 100-25 нет. Диск RP04/05 даёт 88 мегабайт (RM03 67 мегабайт), а не 20 мегабайт из статьи. Называть временный вариант документированной моделью DP нельзя.
- В книге не описан исторический порядок устройств на линиях запросов ПК4..ПК7, поэтому расположение источников BR остаётся неизвестным, это `[GAP]`. Команда `set CHAN BRDEV` задаёт только проверочный список, а не действительно существовавшее оборудование.
- Перфоратор перфокарт (этап P2) отложен: готового исходного кода от MIT нет, адрес регистра и вектор прерывания выдумывать нельзя. Устройство `CR` взято из PDP-11 и не подтверждено документами по машине 100-25.
- Терминалы VT52 и 15-ИЭ-013 внутри машины не воспроизводятся. Есть только устройства `TTI` и `TTO`, соединённые с линией `telnet` программы SIMH.
- В командном интерфейсе ie15 нет способов `pty` и `serial`, только `tcp`, `ssh` и `stdio`. Сравнение изображения на ie15 с виртуальной моделью не проводилось.
