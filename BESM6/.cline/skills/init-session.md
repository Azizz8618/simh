# Навык init-session: инициализация сессии

## Назначение

При старте **каждой** сессии или при вызове `$skill init-session` — ПРИНУДИТЕЛЬНО прочитать
ВСЕ ключевые файлы проекта. Это гарантирует, что агент будет знать:
- правила проекта (`.clinerules`)
- инструкции для агента (`AGENTS.md`)
- справочники (`docs/*.md`)
- карты кода (`.cline/maps/*.map`)
- конфигурацию (.ini, COMMANDS.md)
- справочники агентов (TEAM_AGENTS.md, GENS_AGENTS.md)

## Алгоритм (шаги 1–5, БЕЗ пропусков)

### Шаг 1: Карты кода (автоактуализация)
```bash
./scripts/gen_code_map.sh --check
```
Проверяет все карты `.cline/maps/*.map` и регенерирует устаревшие.

### Шаг 2: Чтение всех *.md файлов проекта (ОДИН вызов read_files)

Читать ВСЕ файлы ОДНИМ вызовом `read_files` (правило Т1):

```
Файлы для чтения:
1. .clinerules                  (глобальные правила проекта)
2. AGENTS.md                    (инструкции для агента — код, архитектура, статус)
3. TEAM_AGENTS.md               (координация агентов)
4. GENS_AGENTS.md               (генератор системы)
5. COMMANDS.md                  (команды проекта)
6. docs/LOGGING.md              (журналирование)
7. docs/ВВОД_АНАЛИЗ.md          (справочник по вводу с перфокарт)
8. .cline/skills/README.md      (индекс навыков)
```

### Шаг 3: Чтение всех карт кода (ОДИН вызов read_files)

```
Файлы карт:
9. .cline/maps/besm6_cpu.c.map
10. .cline/maps/besm6_tty.c.map
11. .cline/maps/besm6_mmu.c.map
12. .cline/maps/besm6_disk.c.map
13. .cline/maps/besm6_defs.h.map
14. .cline/maps/besm6_sys.c.map
15. .cline/maps/besm6_vu.c.map
```

### Шаг 4: Подтверждение инициализации

После чтения ВСЕХ файлов агент ОБЯЗАН:
1. Сообщить пользователю краткую сводку: «Прочитаны N файлов (M токенов).
   Готов к работе. Текущий статус ДКС: ...»
2. Указать, какие файлы были прочитаны и их размер.
3. Не продолжать работу до подтверждения.

### Шаг 5: АВТОМАТИЧЕСКАЯ активация token-saver (ОБЯЗАТЕЛЬНО)

После Шага 4 агент ДОЛЖЕН автоматически (БЕЗ запроса) вызвать навык `token-saver`:

```
$skill token-saver
```

ПРИЧИНА: После чтения всех файлов контекст сессии становится большим.
Активация `token-saver` гарантирует, что в дальнейшей работе агент будет
минимизировать расход токенов (группировка операций, кэширование, краткие ответы).

Это происходит ВСЕГДА — не только при явном вызове `/init-session`, но и при
любом обращении к this skill (в том числе при авто-активации в начале сессии).

АЛГОРИТМ АКТИВАЦИИ:
1. Запоминаем: «token-saver активирован» (флаг в контексте)
2. Далее в сессии — соблюдаем все правила token-saver (группировка, кэширование,
   ограничение строк, краткие ответы)
3. При повторном чтении файлов — НЕ читать те, что уже прочитаны (кэш из Шага 2/3)
4. При поиске — использовать `search_codebase` вместо `read_files`

## Правила выполнения

### ОБЯЗАТЕЛЬНО:
- Читать **все** файлы Listed выше — ни один нельзя пропустить
- Пакетное чтение — ОДИН вызов `read_files` для *.md, ОДИН для .map
- Карты кода читают б Spokane `.cline/maps/*.map`, НЕ полные файлы
- Проверять актуальность карт перед чтением (`./scripts/gen_code_map.sh --check`)

### ЗАПРЕЩЕНО:
- Пропуск файлов («этот уже знаю» — НЕТ, прочитать)
- Чтение полных файлов без предварительной карты (*.map)
- Ответ пользователю до завершения Шага 4
- Пропуск Шага 5 (активация token-saver) — ОБЯЗАТЕЛЬНО
- Несоблюдение правил token-saver после Шага 5

## Когда вызывать

**Вызывать ВСЕГДА в начале сессии:**
1. Первой командой в диалоге (параметр `args: "auto"` — автоматическая инициализация)
2. По команде пользователя: `/init-session` или `$skill init-session`

**Авто-активация:**
- При первом ходе в новой сессии (если контекст пуст)
- При смене темы задачи (если requested «ДКС» → загрузить ДКС-справочники)
