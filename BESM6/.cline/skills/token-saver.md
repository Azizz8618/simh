# Навык экономии токенов

## Основные принципы

### 1. Группировка операций
- Все независимые чтения файлов в ОДИН вызов `read_files`
- Все независимые поиски в ОДИН вызов `search_codebase`
- Все независимые команды в ОДИН вызов `run_commands`

### 2. Ограничение объёма
- Всегда указывать `start_line` и `end_line` при известном расположении
- Использовать `search_codebase` вместо чтения всех файлов
- Читать только необходимые части файлов

### 3. Кэширование
- Не перечитывать уже прочитанные файлы в рамках сессии
- Запоминать извлечённую информацию (адреса, символы)
- Использовать контекст предыдущих ответов

### 4. Краткость ответов
- Отвечать по существу без лишних вступлений
- Использовать таблицы вместо длинных списков
- Примеры кода без избыточных комментариев

### 5. Избегание повторов
- Не цитировать уже показанный код
- Ссылаться на ранее показанные фрагменты
- Использовать сокращённые обозначения

## Шаблоны экономии

### Чтение файлов
```
❌ Плохо: read_files для каждого файла отдельно
✅ Хорошо: read_files([file1, file2, file3]) — один вызов
```

### Поиск
```
❌ Плохо: читать весь файл для поиска функции
✅ Хорошо: search_codebase("function name")
```

### Ограничение строк
```
❌ Плохо: читать весь файл на 5000 строк
✅ Хорошо: read_files с start_line/end_line
```

## Для проекта ДИСПАК

### Известные адреса (кэш)
Не запрашивать повторно:
- ДИСП70 загружается по адресу из modloc.txt
- Таблица экстракодов начинается с Э20
- Регистры: РЭ2, РЭ4, М17 — фиксированные адреса

### Сокращения
- Зона → З (0422 → З422)
- Слово → С (1072 → С1072)
- Левая/Правая → L/R

## Метрики экономии

| Метод | Экономия |
|-------|----------|
| Группировка read_files | 30-50% |
| search_codebase | 40-60% |
| Ограничение строк | 20-40% |
| Кэширование | 30-50% |
| Краткие ответы | 20-30% |

## Применение

При активации этого навыка:
1. Минимизировать количество вызовов инструментов
2. Использовать кэшированную информацию
3. Отвечать максимально кратко
4. Избегать повторов и излишеств
