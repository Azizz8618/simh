# ДКС — терминальный концентратор «Электроника-60» (устройство `DKS`)

ДКС — дисплейный концентратор системы Диспак: микро-ЭВМ «Электроника-60»
(PDP-11-совместимая), связывающая до 24 терминалов с БЭСМ-6. БЭСМ-6
обращается к ОЗУ Э-60 через КАДОПАМ (команды 032/0132); эталонная
реализация стороны ОС — `BESM6/besm6_dks.c`. Здесь PDP-11 изображает саму
Э-60: её ОЗУ на 32К слов (`e60_mem`) живёт внутри устройства, и прошивка
достаёт его через окно `KADDR/KDATA` — как КАДОПАМ в железе достаёт ОЗУ
даже при остановленном процессоре.

Линии терминалов — telnet-соединения на порту `ATTACH DKS`; линии
нумеруются 1..24 (линии TMXR 0..23 соответствуют линиям Э-60 1..24).
Символы — КОИ-7 (7 бит, старший бит игнорируется).

## Регистры Unibus (окно 022 байт, адрес автоконфигурации)

| Смещ. | Регистр | Чтение | Запись |
|-------|---------|--------|--------|
| 00 | `DKS_CSR` | IE 0100, RR 0200 (есть приём), LC 0400 (сменились LSTAT), ATN 1000 (звонок) | IE; MCLR 040000 — общий сброс |
| 02 | `DKS_RBUF` | `линия<<8 \| символ` (линия 1–24) + DV 040000; чтение снимает элемент из FIFO и RX-прерывание | — |
| 04 | `DKS_TSEL` | выбранная линия | номер линии 1–24 |
| 06 | `DKS_TBUF` | — | символ в выбранную линию (КОИ-7, бит 7 игнорируется) |
| 10 | `DKS_KADDR` | адрес окна | адрес слова ОЗУ Э-60 (0–077777); бит 0100000 (AI) — автоинкремент после каждого доступа к `KDATA` |
| 12 | `DKS_KDATA` | слово `e60_mem[канал][KADDR]` | запись слова; запись 077777 со значением 0400 — «звонок» Э-60 (в SIM — активация движка, в HOST — прерывание ATN) |
| 14 | `DKS_KCTL` | статус каналов КРК (0400<<2 = канал 2 присутствует) \| выбранный канал | биты 0–2 — канал окна; бит 0400 — «сигнал БЭСМ-6» (ПРП6 на её стороне; в B2 — кадр моста) |
| 16 | `DKS_LSTAT0` | линии 1–12 подключены | — |
| 20 | `DKS_LSTAT1` | линии 13–24 подключены | — |

Прерывания BR4: `DKSRX` — вектор V (принятые данные), `DKSATN` — вектор V+4
(звонок БЭСМ-6 и изменение состояния линий; после подтверждения прерывания
бит ATN снимается, LC — при чтении LSTAT0/1).

Просмотр ОЗУ Э-60 из SCP: `EXAMINE DKS MEM[<индекс>]` — индекс в **десятичном**
виде (МEM[96] = АБУФS 0140₈, MEM[20480] = 050000₈).

Доступ прошивки: окно видно в пространстве ядра по адресам 0160xxx₈
(сегмент 7 → страница ввода-вывода; при выключенном MMU SIMH отображает
VA ≥ 0160000₈ на PA 017600000₈, как в железе). При адресе авто
конфигурации 017760540₈: CSR=0160540₈, RBUF=0160542₈, TSEL=0160544₈,
TBUF=0160546₈, KADDR=0160550₈, KDATA=0160552₈, KCTL=0160554₈,
LSTAT0=0160556₈, LSTAT1=0160560₈.

## Карта памяти Э-60 (протокол СВЯЗЬ7)

Источник — таблицы svyaz7.be (модуль СВЯЗЬ7 ОС Диспак); сверено с
`BESM6/besm6_dks.c`. Адреса словесные, восьмеричные.

### Системные ячейки

| Адрес | Имя | Назначение |
|-------|-----|-----------|
| 00000 | ячейка 0 | (со стороны БЭСМ-6) запись выбирает канал КРК; чтение возвращает статус (0400<<k) |
| 00002 | номнпр | значение неизвестно, 0 не даёт рспец вмешаться |
| 00140 | **АБУФS** | кольцо Э-60 → БЭСМ-6: +0 источник, +1 приёмник, +2..+5 слоты (маска 3, 4 слота); в слот пишется номер абонента |
| 00146 | **АБУФH** | кольцо БЭСМ-6 → Э-60: та же структура; +1 пишет Э-60 |
| 00154 | **АБФОСS** | системный запрос: +0 код (1 подключить / 3 отключить), +1 линия/терминал, +2 адрес области (для 1: `AREA(n)<<1`) |
| 00157 | **АБФОСH** | системный ответ: +0 = 2, +1 номер терминала ОС, +2 результат (0 ОК, 1 линия занята, иначе нет свободных терминалов) |
| 077777 | **адркс** | звонок: запись 0400 будит Э-60; прочие биты — диагностический след |

Абонент 48 — системные запросы/ответы; абоненты 1–24 — номера линий.

### Области терминалов

`AREA(n) = 01000 + n × 01400`, n = 1..24 (область 1: 02400–03777, область
24: 045000–046377).

| Смещение | Имя | Семантика |
|----------|-----|-----------|
| +0 | STATUS0 | 020000 = ввод готов; снимает ОС |
| +1 | STATUS1 | 020000 = вывод активен; снимает ОС |
| +2 | CMD_IN | Э-60 → ОС: 4 = ввод готов, 5 = вывод завершён |
| +3 | INBUF | байтовый адрес входного буфера: `(AREA(n)+01210) << 1` |
| +5 | CMD_OUT | ОС → Э-60: 4 или 5 = «взять массив» |
| +6 | OUTADDR | байтовый адрес выходного массива (Э-60 читает `>> 1`) |
| +7 | OUTLEN | длина выходного массива в словах |
| +8..+647 | выходной массив | 640 слов = 1280 байт; распаковка по 2 байта на слово (младший, старший), стоп по нулевому байту, символы `& 0177` |
| +648..+767 | входной буфер | 120 слов; упаковка по 2 байта на слово; `INBUF_BYTES = 239` |

### Движок (Э-60 сторона протокола)

Портирован 1:1 из `BESM6/besm6_dks.c`: `e60_post`, `drain_bufh`,
`post_sys_request`, `start_line`, `check_ack`, `post_line_event`,
`pass_input`, `take_output`, `dks_process`. Пост в АБУФS при полном
кольце отклоняется и повторяется на следующем тике; системный запрос
3 (отключение) ответа не имеет — ждёт, пока ОС заберёт запись из кольца.

## Режимы

- `SET DKS ENGINE=SIM` (по умолчанию) — протокол ведёт устройство (движок
  в C); строки терминалов идут через локальное эхо и построчное
  редактирование (`\b`/0177 — забой с эхом `\b \b`, CR/LF — завершение
  строки).
- `SET DKS ENGINE=HOST` — протокол ведёт прошивка Э-60, исполняемая CPU
  (этап B1). Устройство — только «железо»: TMXR → FIFO → прерывание
  `DKSRX` (вектор V), окно `KADDR/KDATA`, `LSTAT0/1` + флаг `LC` + флаг
  `ATN` и прерывание `DKSATN` (вектор V+4).
- `SET DKS TESTOS=ON` — заглушка ОС возвращает набранную строку как
  выходной массив (эхо-обратная петля).
- `SET DKS TESTOS=PROMPT` (по умолчанию) — заглушка ОС выдаёт подсказку
  `DKS> ` (текст пока ASCII, см. открытый вопрос о кодировке).
- `SET DKS TESTOS=OFF` — ОС-сторона отсутствует: линии подключаются, но
  системные запросы не отправляются (для этапа B2 readiness приходит от
  моста).
- `SET DKS BRIDGE=порт` (этап B2) — сервер моста КАДОПАМ на стороне Э-60:
  TCP-порт, на который подключается симулятор БЭСМ-6 (`SET DKS
  REMOTE=host:port` в BESM6). Кадры 8 байт: `D6 op chan ahi alo vhi vlo 00`
  (запрос) / `D7 ...` (ответ); операции: READ 01, WRITE 02, ATTN 03 (Э-60 →
  БЭСМ-6, ПРП 6), PING 04. Ячейка 0 через мост отдаёт статус канала
  (002000), запись 077777 ← 0400 — «звонок» БЭСМ-6, запись ячейки 0 —
  выбор канала. `SET DKS NOBRIDGE` закрывает мост.
- `SET DKS REMOTE=...` — на стороне БЭСМ-6 (`besm6_dks.c`): КАДОПАМ
  превращается в TCP-клиент; локальный протокольный движок отключается,
  ОЗУ Э-60 живёт в другом процессе.

## Отладка

`SET DKS DEBUG=<флаги>` (разделитель `;`): `KADOPAM` (обращения к окну),
`RING` (кольца, системные запросы, записи областей), `IRQ` (прерывания),
`DATA` (символы линий), `PROTO` (состояния линий), `BRIDGE` (кадры моста,
этап B2). Вывод — в поток отладки SCP: `SET DEBUG STDOUT` (или файл).
Дополнительно полезны `SHOW DKS CONNECTIONS`, `SHOW DKS STATISTICS`,
`SET DKS DISCONNECT=n`.

## Тесты (этапы A, B1 и B2)

`PDP11/tests/dks_run_tests.sh [BIN/pdp11] [порт]` — прогон: T1 (подключение
→ sysreq 1 → ответ АБФОСH), T2 (ввод HELLO → выходной массив), T6 (обрыв
telnet → sysreq 3), T8 (звонок с посторонними битами), T12 (забой), окно
`KADDR/KDATA` (запись/чтение/AI/звонок) прошивкой из
`dks_firmware_test.ini`, а также штатный `PDP11/tests/pdp11_test.ini`.

`PDP11/tests/dks_b2_test.sh [BIN/pdp11] [BIN/besm6] [порт]` — приёмочный
тест этапа B2: поднимает ДВА симулятора (Э-60 с `SET DKS BRIDGE=4140` и
БЭСМ-6 с `SET DKS REMOTE=localhost:4140`), ОС-заглушку на БЭСМ-6
(`dks_b2_besm6.ini`, генерируется `gen_os_stub.py`) и телнет-терминал;
проверяет мост (кадры, статус 002000, реплай АБФОСH, звонок в обе
стороны), эхо HELLO через ОС и выходной массив. Порт фиксирован ini (4000).

Замечание по отладочному выводу: логи идут в stdout буферизованно —
тесты завершают симуляторы через Ctrl-E + QUIT и ждут самостоятельного
выхода процесса, иначе буфер теряется.

`PDP11/tests/dks_b1_test.sh [BIN/pdp11] [BIN/besm6] [порт]` — приёмочный
тест этапа B1: движок СВЯЗЬ7 работает как прошивка Э-60 (`SET DKS
ENGINE=HOST`), устройство остаётся только аппаратурой.  Три части:

1. `ENGINE=HOST + TESTOS=PROMPT` (`dks_b1_fw.ini`): цепочка «подключение
   → sysreq → термин → приветствие выходным массивом → эхо прошивкой →
   ответный prompt» — всё это делает прошивка `PDP11/dks_fw.bin`.
2. `TESTOS=ON`: редактирование строки прошивкой (забой BS SP BS,
   эхо результата ОС), обрыв и повторное подключение с освобождением
   терминала.
3. `ENGINE=HOST + BRIDGE=4140` + БЭСМ-6 с ОС-заглушкой (`dks_b2_e60_fw.ini`
   + `dks_b2_besm6.ini`): полный протокол СВЯЗЬ7 через мост КАДОПАМ между
   двумя симуляторами, причём на стороне Э-60 протокол ведёт прошивка.

18 проверок, все проходят; полный набор (`dks_run_tests.sh` + B1) — 23/23.

Прошивка собирается из `PDP11/dks_fw.mac` листинговой сборкой
`PDP11/tests/gen_dks_fw.py` (двухпроходный ассемблер подмножества
MACRO-11; образ абсолютного загрузчика `dks_fw.bin`, листинг `dks_fw.lst`):
`load PDP11/dks_fw.bin` ставит код с 01000, векторы 0300/0304 и PC=START.
Структура прошивки — событийная: обработчики прерываний (0300 DKSRX,
0304 DKSATN) только будят WAIT, вся работа — в главном цикле PROCESS.

Ручной прогон:

```ini
; dks_a_prompt.ini
set dks enable
set dks engine=sim
set dks testos=prompt
attach dks 4000
deposit 200 0777          ; BR . — холостой цикл CPU
go 200
; telnet localhost 4000 -> «E60 DKS ready», «DKS> »
```

## Этап C

1. **BULK-опкоды 05/06** — блочные кадры моста: `BULK_READ 05`
   (запрос 8 байт, ответ 8 + 2·cnt), `BULK_WRITE 06` (запрос 8 + 2·cnt,
   ответ 8).  Данные — только адреса 1..077776: ячейка 0 (выбор канала)
   и звонок 077777 сохраняют одиночные кадры с побочными эффектами.
   Сторона БЭСМ-6 склеивает последовательные возрастающие записи 0132
   в один BULK_WRITE (до 64 слов): массив вывода Диспака (до 640 слов)
   уходит ~10 кадрами вместо 640.  Порядок программы через мост
   сохраняется: любое побочное действие (чтение, ячейка 0, звонок)
   сбрасывает буфер склейки; есть таймерный сброс (раз в секунду).
   Канал кадра маскируется в 0–3 везде (ОЗУ 4 канала КРК; раньше
   канал 4–7 читал/писал память вне массива).
2. **ПРП12 для системных запросов** — пост системного запроса в АБУФS
   (АБФОСН записан, абонент 48) несёт флаг в кадре ATTN (байт 3, бит 0);
   БЭСМ-6 ставит ПРП12 (PRP_DKS_ATTN) вместе с ПРП6 — то, чего ждёт
   СВЯЗЬ7/Диспак (нтерм7, AGENTS.md п. 5.2).  Локальный режим оставлен
   как в эталоне (только ПРП6); пульс KCTL 0400 прошивки — обычный
   ПРП6 (детекции sysreq в прошивке пока нет).
3. **Многоканальность КРК** — БЭСМ-6: `SET DKS CHANS=n` (1–2) открывает
   n клиентов моста; клиент i обслуживает канал 2+i и соединяется с
   портом p+i.  Ячейка 0 отвечается локально по живости клиентов
   (без RTT); 032/0132 маршрутизируются по текущему каналу (нет
   клиента — транзакция теряется с ограниченной отладкой); ATTN ставит
   ПРП своего канала (PRP_DKS_CHAN).  Э-60: `SET DKS CHAN=k` (0–3,
   по умолчанию 2) — бит статуса 0400<<k, байт канала в ATTN, обработка
   звонка/областей.  Ограничение: база канала эталона = 2, поэтому
   возрастающее назначение покрывает каналы 2 и 3.
4. **Кодировка** — `SET DKS ENCODING=KOI7|UTF8` (по умолчанию KOI7 —
   сырые байты протокола, поведение эталона).  UTF8: кириллица
   КОИ-7Н1 (0140–0176, таблица Ю..Ч из besm6_tty.c) выводится как
   UTF-8, ввод декодируется обратно (регистры схлопываются — в КОИ-7
   один регистр); непреобразуемое отбрасывается, обрыв последовательности
   сбрасывается при дисконнекте.

## Диспак/СВЯЗЬ7 (этап C, прогон)

`BESM6/run_test_dks_remote.sh` — конфигурация реального Диспака
(`test_dks.ini`) с `SET DKS REMOTE`: ОС в процессе БЭСМ-6, ДКС — в
процессе Э-60 (PDP-11), весь КАДОПАМ ОС идёт через TCP-мост — как с
настоящей микро-ЭВМ.  Требует образов дисков Диспака (sbor2053.bin и
др.) — их нет в репозитории; приёмочный прогон (логин, печать,
дисконнекты) выполняется на машине с образами по этому сценарию.
